## 结论一：不需要新的用户类型，两个角色就能区分

「物业总公司维修工」和「枫桦景苑管理处维修工」就是**同一套功能勾选、数据范围不同的两个角色**：

- 物业总公司维修工：数据范围 = 全公司；
- 枫桦景苑管理处维修工：数据范围 = 枫桦景苑管理处（自动含其下全部小区）。

这套东西 RBAC 一期已经做完，业务角色页现在就能建。系统据此判断「某维修工能不能被某管理处选为默认维修工」：
**范围覆盖该管理处（全公司，或范围里含这个管理处 / 含它下面的小区）才能选**。总公司维修工自然可以被多个管理处选；管理处维修工只会出现在自己管理处的下拉里。

## 结论二：领料仓库按「工单所在管理处」匹配，而不是按「维修工所属管理处」

Mike 原话是「根据用户所属物业管理处来匹配」。按人算有个漏洞：总公司维修工跨管理处，他没有唯一的「所属管理处」。
按**工单的小区 → 管理处**算，两类维修工都成立，而且材料本来就是从现场那个管理处的仓库领的。
对专属维修工两种算法结果一致，所以建议统一按工单所在管理处。

## 方案

### 1. 报修类型规则挂管理处
- `repair_type_rules` 加 `office_id`（可空 = **公司默认模板**），唯一键改为 (tenant_id, office_id, repair_type)。
- 后台「报修类型配置」弹窗顶部加管理处 Tab：`公司默认 | 枫桦景苑管理处 | …`。
  管理处页**首次打开从公司默认复制一份**（懒复制），之后各改各的，互不影响。
- 取规则的顺序（自动派单、类型关键词判定、「猜你想输」、默认时限一律同一函数）：
  报修小区 → `communities.office_id` → 该管理处规则；没有 → 公司默认。

### 2. 默认维修工下拉按管理处过滤
- 候选 = 勾了「工单池 · 接单」**且**数据范围覆盖该管理处的人；公司默认页 = 全公司范围的人。
- 保存时服务端同样校验，不合规 400：「王师傅是枫桦景苑管理处的维修工，不能选为吴泾管理处的默认维修工」。
- `/work-orders/technicians` 增加 `officeId` 查询参数，派单弹窗也按本单管理处过滤（顺手把派单选错人的口子堵上）。

### 3. 领料仓库自动匹配
- `warehouses` 加 `office_id`（可空 = 公司总仓）；`community_id` 由迁移回填成 `communities.office_id` 后废弃。
- **删掉** `repair_type_warehouses` 表和后台那一列「领料仓库（先选小区）」。
- 「从库存选」默认仓：本单管理处的启用仓库（多个时取第一个，允许手动切换）→ 没有则公司总仓 → 再没有才提示「请在『库存与采购』里给 XX 管理处建一个仓库」。
- 员工端小程序只改提示文案，接口返回结构不变。

### 4. 迁移
- `repair_type_rules.office_id` 默认 NULL：现有数据自动成为公司默认，零停机。
- `warehouses.office_id` 从 `community_id` 回填；`repair_type_warehouses` 留一个版本再删。

### 5. 影响面与工作量
后端：规则 CRUD / 自动派单 / stock-options / technicians 四处 + 两条迁移；
后台：报修类型配置弹窗改 Tab、库存页仓库表单加「所属管理处」、派单弹窗按管理处过滤；
员工端：提示文案 + 重新发包（推送 = git / API / 小程序包三件事）。
估计 1.5～2 个工作日，可以拆成「仓库匹配」「规则按管理处」两次上线。

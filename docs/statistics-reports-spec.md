收费明细行语义：
- 一行 = 某房屋某收费项目某所属年月的一笔应收；`paid_date` 为空 = 未缴（欠费）；有值 = 该笔已收（含历史补缴），`refund_date` 非空 = 退款/红冲行（280 行，金额有正有负，全部带 paid_date）。
- 全库负金额行 1,325 行（退款/红冲），净实收 = Σ amount_cents。
- 收款日期 `paid_date` 只有日期精度；登记时间 `source_updated_at` 不是收款时间。

## 2. 已核对口径：项目欠费年度汇总

**公式**（与旧系统截图逐格核对一致）：

```
行：管理处 office_code（按选择多选；没数据的年份显示 0.00）
列：年度 = substr(bill.period, 1, 4)
值：Σ bill.amount_cents
     WHERE bill.paid_date IS NULL
       AND bill.fee_code IN (选中收费项目)
       AND room.nature IN (选中房屋性质)   -- 需要 join mis_mirror_room
       AND 年度 = 列年度
合计：Σ 全部年度（同筛选）
明细（点单元格）：按房屋聚合
     地址 bill.address、业主 bill.owner_name、建筑面积 room.area_sqm、
     欠费年月范围（该房屋当年未缴 period 的首末，如 201410-201412）、金额 Σamount_cents
再下钻：该房屋逐笔账单 zj_id / 收费项目 / 所属年月 / 金额 / 收款日期 / 收款方式 / 收款人
```

## 4. 实现方案（首批）

### 4.1 后端

新增只读报表接口（`apps/api/src/modules/statistics/`）：

- `GET /api/v1/statistics/options`
  返回：管理处列表（office_code/name/PMS communityId）、收费项目（16）、房屋性质（代码+中文名）、年度范围、数据截止时间（镜像 synced_at）、数据源模式。
- `GET /api/v1/statistics/annual?type=arrears|received&years=2004..2026&officeCodes=01,02&feeCodes=01&natures=01,04&asOfPeriod=202612`
  返回：`{ columns:[{year}], rows:[{officeCode,officeName,cells:{year:cents},totalCents}], subtotal:{...}, dataAsOf, filters }`。
  - arrears：`paid_date IS NULL`，年度=period 年；received：`paid_date` 年度分组，Σ 含退款负数。
- `GET /api/v1/statistics/annual/detail?type=&officeCode=&year=&feeCodes=&natures=`
  返回房屋级明细：address、ownerName、areaSqm、periodRange、amountCents、sId/zhId；合计与单元格金额必须相等。
- `GET /api/v1/statistics/annual/detail/bills?officeCode=&sId=&year=&feeCodes=&natures=`
  返回逐笔：zjId、feeName、period、amountCents、paidDate、refundDate、paymentMethod、cashier。
- 权限：复用 `business:view`（报表页 key 可后续新增 `reports`）；数据范围：管理处→PMS 小区映射过滤（全公司账号看全部）。
- 金额一律整数分；接口返回 `dataAsOf`（镜像最近成功同步时间）；mirror 未覆盖的表不返回假 0，写清“缺数据”。
- 测试：fake repo/聚合函数单测 + 用生产镜像同条件 SQL 的期望值断言（02 管理处验收数）；金额分↔元格式测试。

### 4.2 前端（apps/neighbor-web）

- 新页面 `/statistics`（菜单「统计汇总」，rail「统计」），左侧筛选：
  - 管理处/小区：勾选多选（全选、反选、搜索）；
  - 收费项目：16 项勾选（默认全选，或按旧系统默认）；
  - 房屋性质：勾选（01商品房、04配套用房、05、06商铺、07居住、08非居住…）；
  - 收款截止日期、应收截止年月；
  - 「统计」按钮 + 「导出 Excel/CSV」。

## 6. 01 管理处历史欠费差异——已定位根因（2026-11-09 23:0x，MIS 只读验证）

**结论：旧报表的「房屋性质」口径用的是收费明细行上的房屋性质 `WYZJ.FWXZ_DH`（收费发生时点的性质），不是室表当前房屋性质。** PMS 镜像目前只镜像了室表当前性质（`mis_mirror_room.nature`），所以把 2007–2018 年按「空房」计费的历史欠费也算进了「商铺」，导致 01 管理处多算 ¥232,344.20。

MIS 只读实测（01 管理处、管理费、未缴，按行级 `FWXZ_DH` 分年汇总）：

| 年度 | 行级房屋性质 | 金额 | 截图是否计入 |
|---|---|---:|---|
| 2004 | 01 商品房 | ¥444.40 | 计入 |
| 2005 | 01 商品房 | ¥480.30 | 计入 |
| 2007 | 06 空房 | ¥54,321.80 | **不计入** |
| 2008–2015 | 06 空房 | 每年 ¥21,226.80 | **不计入** |
| 2016–2018 | 06 空房 | 每年 ¥2,736.00 | **不计入** |
| 2024 | 01 商品房 | ¥4,669.20 | 计入 |
| 2025 | 01 商品房 | ¥10,885.20 | 计入 |
| 2026 | 01 商品房 ¥481,868.70 + 04 商铺 ¥163,921.20 | ¥645,789.90 | 计入 |

把「06 空房」剔除后 2004+2005+2024+2025+2026 = **¥662,269.00，与旧系统截图完全一致**；02 管理处 2011/2012/2014/2025/2026 与合计也同时保持一致（02 无空房行）。

其他已确认的字典（来自 MIS `设置管理处`、`FWXZK`、`WYZJ`）：

- `WYZJ` 还有 `GYD` 列（值 01/02/03/04/09/10，与 5 个管理处不对应，不能直接当管理处用；管理处归属用楼表/室表更可靠，现有镜像口径与截图一致）。

### 修复方案（P1.1）
1. `mis_mirror_bill` 增加 `nature_code`（源 `WYZJ.FWXZ_DH`），镜像 upsert 带上；`row_hash` 纳入该字段。
2. 年度汇总/明细的房屋性质过滤改为按 `bill.nature_code`（为空时回退室表 nature，并在文档标注）；`options.natures` 返回 FWXZK 全 14 项中文名。
3. 前端默认房屋性质勾选：除「06 空房」外全选（复刻截图口径；用户可手动勾上空房）。默认条件重算 01 = ¥662,269.00、02 = ¥745,182.10。
4. 上线后对镜像做一次全量重灌（已有接口 `POST /fees/mis/mirror/reload`，低峰约 2 分钟，只读 MIS），否则历史行没有 nature_code。

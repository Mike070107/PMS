# 目标达成与经营决策大屏

## 入口与边界

- 正式前端路由 `/screen`，后台“分析 → 大屏设置”路由 `/screen-settings`；沿用 fees:view / fees:edit，服务端同样校验权限。
- 小程序、Windows 助手不涉及本轮变更。大屏原有小区多选、年度选择、全屏、每5分钟自动刷新保留；隐藏页面不轮询，回到页面立即更新。
- 实收复用 `/fees/mis/screen-summary`，现固定读取定期同步的本地镜像，不再跟随全局数据源开关或回退直连MIS。小区选项通过 `/fees/screen-options` 读取本地授权范围。没有修改连接身份、同步任务、凭据或读写方向。镜像返回真实 `dataAsOf`，页面不把浏览器读取时间当作同步时间。
- 本轮新增数据只写 PMS `tenant_configs` 与已有 `collection_targets`，不向 MIS 写回，不修改真实收费记录，不需要新表迁移。

## 数据口径

1. 实收只累计目标组对应费项、所选小区、所选年度、截至北京时间当前自然日的有效收款。未发生日期不进入累计。目标组未被完整选中时不摊分目标，不伪造小区目标。
2. 截至今日计划：前面月份计划总额 + 本月计划 × 今日日期 / 本月自然日数。缺少月度计划沿用既有年度/12参考，界面明确标识；新设置强制12个月合计等于年度目标。
3. 落后金额 = 截至今日计划 − 目标范围实收。风险项目按落后金额倒序；领先项目不会显示为负欠款。
4. 剩余需收 = max(0, 年度目标 − 累计实收)。所需日均 = 剩余需收 / 年内剩余自然日（含今日），向上取整到分。超额完成后为0。
5. 近28日日均使用截至昨日的完整自然日，年初不足28天采用已有自然日。与目标费项一致，不用所有费项今日实收比较单一费项目标。
6. 趋势估算 = 当前累计 + 近28日日均 × 今日之后剩余自然日；排除重复预测今天。历史年、未来年、无目标或不足14个完整自然日不预测。虚线与“趋势参考，不作为回款承诺”常驻；未来计划保留月度季节性。
7. 年度回款目标完成率与当期账单收缴率不同。沿用已有数据源有效收款定义，不凭大屏推断利润、现金余额、未来应收或账单所属期；当前上游不支持的财务分类不虚构。

## 大屏设置

- 目标与月度计划复用既有目标表。新增指标组先填100万元示例，按分精确分配12个月尾差；必须选择真实授权小区并勾选核实确认，才作为正式目标保存。不会后台自动种入生产指标。
- 人工区域初次显示带“示例”标识的默认数值；设置页同样预填。可以保持示例标识保存，也可以核实后取消示例标识，填写真实台账日期与说明。
- 人工字段：承诺逾期户数/金额、大额欠费未跟进户数/金额、争议件数/金额、近30日跟进后回款、到期承诺笔数、已兑现笔数、待跟进户数，以及各小区负责人。
- 兑现率 = 已兑现承诺数 / 同一统计窗口内到期承诺数；分母为0显示“—”，不显示0%。兑现数不得大于到期数。
- 金额以元输入、分存储、万元展示；件数/户数/笔数为非负整数。截止日期属于所选年度；正式数据不得在未来。超过7天未更新提示数据日期。
- 人工台账按租户 + 年度 + 精确的小区ID集合隔离。选择子集时不会拿全公司人工汇总替代。负责人同该配置保存；账号/公司/管理处切换立即清除旧数据。
- API为 `GET/PUT /fees/screen-settings`、`PUT /fees/screen-targets`。写入记录创建人/更新人与时间。人工配置使用revision乐观锁，冲突返回409，不自动覆盖；网络未知结果只查询一次原操作，不自动重写。
- 表单空值/无效金额/合计不符时红框、字段旁错误、aria关联并聚焦首错；失败保留输入。只读账号看得到设置，控件禁用，API禁止写入。
- 台账数值不伪装为逐户待办，没有逐户记录时不提供虚假的“分配跟进”“查看名单”操作；后续接入结构化跟进记录后再支持明细下钻。

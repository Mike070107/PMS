# PMS 开发与交付流程

约束见 CLAUDE.md；旧历史见 Git。不强制 /start、/ship、Shift+Tab 或某种旧版浏览器工具。

## 开始与实现

1. 检查目录/分支/工作区，需求明确就推进。并行任务先协调或隔离 worktree，不共用索引。
2. 说清范围和完成条件；功能清单逐项记录状态，只读相关文档。
3. “全部待发布”仍要排除草稿、秘密和产物，不用 git add .。
4. 从最新 main 创建 codex/<任务>，复用既有实现，完成后合回 main；冲突核对，不破坏性重置。

## 验证

- 修复先形成失败证据，再补长期回归。停车 test:access-card + test:parking-owner，助手 --self-test；均不代替现场硬件验收。
- UI 使用当前允许的浏览器工具，确认本次源码。生产默认只读；写测试用隔离数据，真实旧库/硬件另留证据。
- 必要类型检查/构建通过再提交。同一输入哈希的有效证据可复用，预览正常不证明正式入口接通。
- 权限拒绝按授权流程处理，不绕过；无法操作真实设备就说明未测。

## 发布

1. 当次用户明确授权后核对 DNS、实例、目录、运行服务；唯一生产 124.223.179.214。
2. 合并推送 main，运行 node deploy/mark-deployed.mjs status；按源码差异，不按提交数量判断各目标。
3. ./deploy/publish-production.ps1 -Target auto：回归、冻结来源、构建、上传、公网核验、标记；依赖不变不重复上传 node_modules。
4. Web/API 核对公开版本与制品；助手清单含版本、兼容下载地址、SHA-256，下载文件校验。发布不等于现场安装。
5. 交付修复项、各端版本/提交（未变也说明）、实际测试、现场未升级、未验证项。写队列/设备回执/现场验证分开报告。

发布日志 deploy/DEPLOY_LOG.md；机器证据 artifacts/release-checks/；人工业务证据/缺口记到已有模块文档。证据必须匹配本次源码。

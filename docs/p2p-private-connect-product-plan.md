# PMS 私有连接产品规划

> 状态：方案设计，尚未开发、测试或部署。
>
> 目标：在现有“公网域名 + 腾讯云中转 + 微信扫码”的 Web 发布能力之外，增加“访问端与发布端直接建立端到端加密连接，直连失败自动中继”的私有连接能力，适用于数据库、文件服务、远程桌面和大流量内网应用。

## 一、结论与产品边界

PMS 保留两条互补的数据路径，不用 P2P 替换现有 Web 网关：

1. **免安装 Web 发布**：用户直接打开 `xxx.prsznh.cn`，扫码后访问；流量经过腾讯云网关。适用于用友、OA、Web 管理后台。
2. **PMS 私有连接**：访问电脑安装访问端，优先与内网发布端建立 P2P 加密隧道；穿透失败时自动切换到 PMS 加密中继。适用于 SQL Server、MySQL、文件传输、RDP 和高流量应用。

首版不把数据库端口直接暴露在公网，不允许只凭域名和公网端口连接数据库。PMS 只建立受控网络通道，数据库自身账号、口令和权限仍由数据库管理。

## 二、竞品调研结论

### 花生壳/向日葵体系

花生壳的核心体验是“安装发布客户端 → 云端增加 HTTP/HTTPS/TCP/UDP 映射 → 获得外网地址”，并提供访问密码、时间、地区、IP 等访问规则。它适合简单公网映射，但流量和带宽依赖服务商线路及套餐。向日葵更偏向已安装两端程序后的远程控制产品。

可借鉴：

- 映射配置对业务人员友好，隐藏 NAT、端口和证书细节；
- 发布端长期在线、托盘可见、诊断清晰；
- 远程访问产品同时具备设备绑定和账号授权。

不直接照搬：

- PMS 不把数据库服务做成裸公网端口；
- PMS 授权对象是“用户 + 访问设备 + 具体应用”，不是共享访问密码；
- 带宽不默认依赖中心服务器，优先建立端到端直连。

### Tailscale / NetBird

共同架构是“身份和策略在控制面，业务流量在加密数据面”：客户端登记设备公钥，控制面只把允许互联的节点和策略发给双方；双方通过 UDP/ICE/NAT 穿透尝试直连，失败才走端到端加密的中继。直连和中继的区别主要是性能，密钥均留在设备本地。

这是 PMS 最适合采用的总体模型：

- 控制面复用 PMS 用户、组织、应用授权和审计；
- 数据面采用 WireGuard 类端到端加密隧道；
- Signal/STUN 只协商地址，不承载正常业务流量；
- Relay 只转发密文，不能解密数据库或应用内容；
- 策略默认拒绝，只下发被授权的目标应用，不把整个局域网暴露给访问端。

### FRP XTCP

FRP XTCP 支持 P2P 打洞，成功后业务流量不经过 `frps`；也能在打洞失败后回退到 STCP。它适合作为 PMS 的快速技术验证，但官方也明确说明打洞成功率受 NAT 类型影响，稳定性不能保证。

规划结论：

- **验证版**可以基于现有 FRP 能力增加 XTCP + STCP 回退，快速验证真实网络成功率；
- **正式产品内核**优先评估 WireGuard + ICE + 自有 Relay，或合规集成成熟组件；
- NetBird 客户端代码为 BSD-3-Clause，但其新版 management/signal/relay 目录采用 AGPLv3，若复用服务端必须先完成许可证评估或取得商业授权，不能直接复制后闭源发布。

## 三、安装形态

只维护一套产品和升级通道，安装时选择角色；不开发三套互不兼容的软件。

### 1. 内网发布端

安装在财务室、机房或门店的常开 Windows 电脑：

- 访问局域网内目标 IP/端口；
- 保持控制面在线并发布连接候选；
- 接收当前设备被分配的应用清单；
- 执行本地端口白名单，不允许访问清单之外的局域网目标；
- 作为 P2P 对端，必要时连接加密中继。

### 2. 外部访问端

安装在员工笔记本或运维电脑：

- 绑定 PMS 用户和本机设备身份；
- 展示本人有权访问的应用；
- 点击应用后，在本机只监听 `127.0.0.1` 的临时端口；
- 自动启动已登记的程序，或把本地地址复制给用户；
- 显示 `P2P 直连 / 专用中继 / 中心中继`、延迟、连接时长和权限到期时间。

示例：访问端把 SQL Server 映射为 `127.0.0.1:31433`，SSMS 连接该地址；内网发布端再转到 `192.168.110.251:1433`。

### 3. 一体端

同一安装包同时启用发布与访问能力，适用于总部电脑既发布本地应用、又访问其他门店资源的场景。界面按“我发布的应用”和“我可访问的应用”分区，后台仍是同一个 Windows 服务、设备身份和更新机制。

## 四、组件架构

```text
                     ┌──────────────────────────────┐
                     │ PMS 控制面                   │
                     │ 用户/设备/应用/策略/审计      │
                     └──────────┬───────────────────┘
                                │ HTTPS/WSS 控制通道
              ┌─────────────────┴─────────────────┐
              │ Signal + STUN                    │
              │ 只做发现、协商和在线状态            │
              └─────────────────┬─────────────────┘
                                │
访问端 127.0.0.1:本地端口 ── WireGuard/ICE P2P ── 发布端 ── 内网 IP:端口
              │                 失败时                 │
              └────── PMS Relay（只转发端到端密文） ───┘
```

控制面和数据面必须分离：控制面被攻破不应直接获得既有会话明文；Relay 不持有设备私钥；设备私钥不上传 PMS。

## 五、授权设计

授权分为四层，任何一层失效都不能建立新连接。

### 1. 设备登记

- 管理员创建“内网发布设备”或用户申请“访问设备”；
- 首次安装使用十分钟有效、使用一次即失效的配对密钥；
- 客户端本机生成设备密钥对，私钥由 Windows DPAPI/密钥存储保护；
- PMS 保存设备公钥、角色、所有者、版本、风险状态，不保存设备私钥；
- 管理员可单独吊销设备，吊销后控制通道、会话申请和中继均拒绝。

### 2. 用户登录

访问端采用 OAuth Device Authorization 类流程：

1. 访问端展示二维码和四位核对码；
2. 员工使用 PMS 小程序扫码，确认“设备名称、应用范围、登录地点”；
3. PMS 把当前 Windows 设备绑定到员工，而不是把微信票据直接交给客户端；
4. 首次绑定后签发短期访问凭据和可轮换刷新凭据；长期凭据绑定设备密钥并由 DPAPI 保存。

默认不要求每次连接都扫码：普通应用可在可信设备上保持 7～30 天设备登录；财务数据库等敏感应用可以配置“每次连接确认”“每天首次确认”或“Windows Hello 二次确认”。

### 3. 应用授权

管理员授权的最小单位为：

`用户/用户组 + 访问设备条件 + 应用 + 协议与端口 + 有效时间 + 会话策略`

应用策略示例：

- 叶双可以从已批准 Windows 设备访问“财务 SQL”，仅 TCP 1433；
- 有效期至 2026-12-31，每天 08:00～20:00；
- 单次会话最长 8 小时，空闲 30 分钟断开；
- 新设备首次访问必须小程序确认；
- 禁止访问财务网段的其他 IP 和端口。

### 4. 单次连接票据

访问端点击应用时，PMS 再次检查用户、设备、应用、时间和风险状态，并签发 30～120 秒内必须使用的一次性连接票据。票据绑定：

- 访问设备公钥；
- 发布设备公钥；
- 应用 ID、目标协议和目标端口；
- 会话 ID、签发时间、到期时间和策略修订号。

双方校验 PMS 签名后才建立数据通道。票据不得包含数据库密码。权限撤销后禁止新建连接；对“立即失效”的应用，控制面推送断开命令，设备同时使用短租约避免推送丢失后无限保持。

## 六、应用模型

在现有 `ExternalAccessApp` 基础上扩展，不另建平行的应用系统：

- `accessMode`: `public_web | private_connect | both`
- `protocol`: `http | https | tcp | udp`
- `targetHost` / `targetPort`
- `launchType`: `browser | local_port | executable`
- `preferredLocalPort`（可选，冲突时自动换端口）
- `directPolicy`: `prefer_p2p | relay_only | direct_only`
- `reauthPolicy`: `trusted_device | daily | every_session`
- `idleTimeout` / `maxSessionDuration`
- `allowedDeviceGroups` / `allowedUserGroups`

Web 应用可以同时提供两种入口：外部临时访问使用公网域名；固定员工安装访问端后使用私有直连。两种入口共用同一应用、人员授权和审计记录。

## 七、连接状态机

1. 访问端申请应用会话，控制面返回短时票据、对端公钥和候选地址；
2. 双方先经 Signal 交换 ICE 候选；
3. 并行探测 IPv6、局域网直连、UDP NAT 穿透；
4. 在限定时间内选取最低延迟直连路径；
5. 直连失败后优先使用同区域/同企业的 Peer Relay；
6. 再失败才使用腾讯云中心 Relay 的 QUIC；
7. UDP 被封锁时使用 `WSS 443` 中继作为最后兜底；
8. 会话期间周期性重试更优路径，可从中继无感升级到 P2P；
9. 网络切换后重新协商，不复用过期票据。

界面必须如实显示当前路径，不能把“已连到控制面”显示为“P2P 已连接”。

## 八、安全基线

- 数据通道端到端加密，Relay 只见密文和必要的连接元数据；
- 每台设备独立密钥，禁止全体客户端共享平台 Token；
- 默认拒绝、应用级路由，不给访问端整个 LAN 的任意访问权；
- 本地监听默认仅绑定 `127.0.0.1`，禁止默认监听 `0.0.0.0`；
- 发布端校验票据中的目标与本地获批配置完全一致，拒绝客户端自报 IP/端口；
- 管理员、用户、设备、应用、连接票据和实际会话全部记审计日志；
- 日志不记录数据库口令、设备私钥、会话密钥和业务数据；
- 更新包必须签名并校验版本、哈希和回退链路；
- 支持设备吊销、密钥轮换、版本下限和高风险版本强制停止连接；
- 数据库仍使用最小权限账号、TLS 和自身审计，隧道授权不能替代数据库认证。

## 九、后台和客户端交互

### PMS 后台

新增应用时先选访问方式：

- `浏览器直接访问`
- `安装访问端后私有连接`
- `两种方式都提供`

选择私有连接后，管理员只填写应用名称、协议、内网 IP/域名、内网端口、发布设备和授权用户；公网域名不是必填项。发布状态改为：

`配置下发 → 内网探测 → 发布端在线 → 授权策略生效 → 直连/中继可用`

### Windows 客户端

一个安装包，首次运行选择：

- `发布本地网络中的应用`
- `访问公司授权的应用`
- `两者都需要`

角色以后可由管理员授权后切换。访问列表以应用为中心，不展示虚拟网段、WireGuard、公钥或 FRP 参数。数据库卡片提供“一键打开 SSMS”和“复制本地连接地址”。

## 十、实施阶段

### 阶段 0：真实网络验证

不改生产业务入口，制作两端实验程序，至少覆盖：

- 公司宽带 ↔ 家庭宽带；
- 移动热点 ↔ 公司宽带；
- 双方均在运营商 CGNAT；
- 企业网络封锁 UDP；
- 断网、换网、睡眠唤醒和客户端升级。

记录直连成功率、首连耗时、吞吐、延迟、回退时间和重连时间。只有实测结果才能决定 FRP XTCP 是否足以支撑首版。

### 阶段 1：TCP 私有连接 MVP

- 发布端、访问端和一体端共用现有助手外壳、服务、托盘和升级机制；
- 支持 TCP 应用、本地回环端口、一次性设备配对和小程序登录；
- 实现用户 + 设备 + 应用授权及短时连接票据；
- P2P 优先、STCP/WSS 中继兜底；
- 首批支持 SQL Server、MySQL、自定义 TCP；
- PMS 展示实际路径、延迟和失败原因。

### 阶段 2：正式加密数据面

- 根据阶段 0/1 证据选择 WireGuard + ICE 内核；
- 上线自托管 Signal、STUN 和端到端加密 Relay；
- 增加 UDP、路径迁移、Peer Relay 和多中继节点；
- 完成第三方许可证、安全审计、渗透测试和密钥轮换演练。

### 阶段 3：应用体验与规模化

- 注册应用启动器（SSMS、Navicat、RDP、自定义程序）；
- 设备组、用户组、临时授权审批、到期回收和连接报表；
- 发布端双机热备与同一应用多出口；
- 国内多区域 Relay、容量告警和带宽成本看板。

## 十一、MVP 验收标准

- 新访问电脑只需安装一个正式安装包并扫码绑定，不执行 PowerShell；
- 未授权用户、未批准设备、过期票据、被撤销授权均无法建立 TCP 会话；
- 访问端只能连接被授权应用，不能扫描或访问同网段其他地址；
- P2P 成功时，抓包和服务器流量证明业务数据没有经过腾讯云；
- P2P 失败时，10 秒内自动切到加密中继，业务能够继续；
- PMS 和客户端均准确显示当前是直连还是中继；
- Relay 无法解密业务流量，数据库仍要求自身账号认证；
- 客户端重启、Windows 重启、断网恢复、换网和升级后均能恢复；
- 取消授权后，新连接立即拒绝，配置为“立即失效”的现有连接在规定时间内断开；
- 所有连接都有用户、设备、应用、路径、开始/结束时间和结果审计。

## 十二、正式开发前需要冻结的决策

1. MVP 是先用 FRP XTCP 验证，还是直接引入 WireGuard/ICE 内核；
2. 访问端支持的首批应用：建议 `SQL Server + MySQL + 自定义 TCP`；
3. 普通应用可信设备登录期限，以及财务类应用的二次确认频率；
4. 中继容量目标和并发连接上限；
5. 是否允许员工自助登记访问设备，还是必须管理员批准；
6. 第三方网络内核的许可证与商业分发方案。

# 公寓、单栋办公楼和商铺地址录入

## 已确认的业务结构（2026-09-19）

- 馨香公寓吴泾店管理处 → 馨香公寓吴泾店 → 1号楼 → 101室。
- 吴泾物业总公司管理处 → 吴泾物业总公司（单栋办公楼，无楼号）→ 3楼 → 财务部。
- 管理处仍在「管理处」页面建立；公寓和办公楼名称在房产管理的「管理」中建立并关联管理处，不把管理处再建成小区。

## 录入方式

房产管理 → 新增房产：类型支持住宅、公寓、办公楼、商铺。

- 公寓：选择所属公寓，楼栋号填 `1`，房号填 `101`；没有弄号或路名可留空。
- 单栋办公楼：选择所属办公楼，楼栋情况选「单栋（无楼号）」，楼层填 `3`，房间／部门填 `财务部`。无需楼栋号和编造的数字室号。
- 有真实楼栋号或沿街门牌的办公楼：选「有楼栋号／门牌号」再填真实号码，楼层不是楼栋号。
- 商铺：真实门牌号和铺位／位置名称，另填商铺名称；名称参与语音地址匹配。

保存、编辑和地址显示共用规范位置文本。办公楼楼层及房间存入既有 `room_no`（如 `3楼财务部`）；单栋无编号楼的 `building_no` 为空字符串，并以现有 `building_id` 关联多个部门。无需数据库结构迁移，不写假 `1号楼`、不改历史房产。

## 语音匹配与安全边界

- 只说 `5530弄` 时，系统会用真实楼栋档案反查小区；当前管理范围内唯一时识别到小区级，多个小区共用同一弄号且无上下文时不猜。再说「12号101室」可继续精确到房产。
- 说「小区简称 + 已建公区点位」时可自动预填：「永南门卫室」先用「永南」收窄小区，再用「门卫室」收窄点位。若永南150弄和永南5511弄仍同名，按小区列表的稳定顺序预填第一个，用户仍可修改；完整念出「永南5511弄」时必须优先完整名。只说「门卫室」且多个小区重名时仍不猜。
- `3楼财务部`、`三楼财务部`、`三层的财务部`、`第三楼的财务部`归一为同一真实位置。
- 没说楼层但部门唯一时可按名称定位；不同楼层／楼栋同名且无法收敛时不任意选第一间。说了 13楼不能匹配到3楼，地下3楼不能匹配地上3楼。
- 新档案由识别接口实时查数据库，不依赖重新训练。麦克风转写和方言识别仍受 ASR 服务能力影响；自动测试验证的是转写文本到地址的匹配，不代表真机录音已验收。

## 已证实的返工原因和预防

2026-09-19：后台只有住宅／商铺，并把「号」和「室」固定必填，单栋无编号办公楼无法按真实地址录入。仅提示往「室」里填部门名称没有解决楼号必填。适配必须同时覆盖表单、服务端约束、编辑回显、各端格式化和语音匹配；不让用户伪造编号以迎合住宅模型。

2026-09-20：删掉最后一户房产后，楼栋和自动生成的楼栋二维码仍保留；删小区只数楼栋，因此明明无房产仍提示「请先删除房产」。删除小区改为先数真实房产和历史工单：有房产报户数；有历史工单报可搜索单号并保留地址档案；两者都没有才在一个事务内清理空楼栋、单元、公区点位和废二维码。自动验收覆盖这三个分支。

2026-09-20：语音地址规则已能抽出弄号，但紧接着又因「没有几期或几号」将弄号候选整段丢掉，所以单说 `5530弄` 必然识别不到。修复后弄号必须再撞真实楼栋库，不允许不验证就用字符串猜小区。

2026-09-20：旧规则只认整句里的完整小区名，「永南门卫室」既不包含完整的「永南150弄」，又因永南150弄和永南5511弄都有门卫室被当成歧义，因此退回「没认出地址」。修复为先取语句中最长的小区名前缀，再撞已建点位；只在明确听到「简称 + 点位」时允许多个结果按列表顺序预填第一个。自动验收覆盖用户原话、ASR 把「个」转成「各」、完整小区名优先以及未念小区时仍不猜。

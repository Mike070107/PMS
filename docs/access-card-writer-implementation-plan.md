# 枫桦景苑门禁卡授权实施计划

> 2026-10-15 现场基线：ACR122U 已在 Windows PC/SC 下识别；测试卡 UID `07B2DF06` 已从未加密空白卡真实写成枫桦景苑已加密初始卡，再写成大铁门授权卡；每阶段重新连接后 16 扇区认证和逐块回读均通过。用户现场确认该卡可在枫桦景苑大铁门正常刷卡。本轮未改捷顺数据库，因此只证明实体卡与现场门禁链路，不代表原捷顺软件已可查。

## 已核实事实

- 实体卡为 MIFARE Classic 1K；ACR122U 支持加载密钥、A/B 密钥认证、16 字节块读写和回读。
- 制造商块 `0/0` 永久禁止写入；当前实现连整个 0 扇区都不写。
- 捷顺 `MC.CardInfo.IDNO` 与 PC/SC 读到的 UID 字节序一致。
- 卡内 12–15 扇区指定块前两字节是大端 ICNO；样卡 `55FC` 与数据库十进制 `22012` 一致。
- `MC.CardInfo` 有 20 列，`IDNO` 和 `ICNO` 均有索引；现库 11629 行、数字 ICNO 最大值 30499，空 ICNO 存在两条，不能用“行数 + 1”分配。
- ACR122U 不需要固定电脑：插入任一安装发卡助手的 Windows 电脑即可。数据库密码只保存在 `.80` 助手。

## 目标链路

1. 管理员先用独立的“门禁卡加密初始化助手”将采购空白卡批量制作为本小区初始卡；该助手不连 PMS、不分配 ICNO、不写业主权限。
2. PMS 网页只创建“已初始化卡的大铁门授权”任务；普通空白卡不得在 PMS 发卡。
3. API 只把任务分配给当前在线且上报 ACR122U 的 `issuer` 助手。
4. 发卡助手只接受已加密初始卡；未加密空白卡、已发卡和外来卡均停止写入。
5. API 通过 `.80` 助手分配未使用 ICNO，发卡助手将它和大铁门授权一并写入卡片并整卡回读。
6. 卡写成功后，`.80` 助手在单一事务中创建/关联 `HR.Person` 与 `MC.CardInfo`，然后按 UID、ICNO、PersonID 回读。
7. 页面分别展示“实体卡已写”和“捷顺库已登记”；入库失败只续传数据库，不重写卡。

## 解锁与发布条件

- 助手只在 ACR122U 与 DPAPI 加密卡模板同时就绪时上报 `cardWrite=true`。
- `.80` 助手的人员与卡片写入使用单一串行化事务；网络未知结果重试时先按 UID+ICNO 回读，不重复建人或建卡。
- 真库新增和原捷顺软件查询留给用户本次完整验收；未验收前不宣称该环节业务完成。
- 测试环境确认后可发布；生产发布仍需当次明确授权。

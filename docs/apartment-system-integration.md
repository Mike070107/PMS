## 迁移约束

1. 先生成只读映射报告，不直接更新 PMS。
2. 唯一匹配才能进入联系人合并：空白字段可补齐，完全相同跳过，姓名或手机号冲突进入人工确认。
3. 收费订单保留旧地址文本、旧地址 ID 和旧订单 ID，写入时使用幂等键，重复执行不得重复入账。
4. 未匹配地址、范围房号和冲突联系人不得自动选择“最像”的 PMS 房产。
5. 导入前备份，先在测试环境全量演练；对账通过后另行取得生产写入授权。

## 已确认的收费界面与住户资料规则

- 收费工作台选择楼栋时只显示完整楼栋名称（例如 `A栋34号`），不附带房间数量。
- 选择房间后，姓名和手机号从 PMS 业主用户信息带出，不以旧地址表作为实时主资料。
- PMS 暂无姓名或手机号时允许收费员补录；收费员在工作台修改姓名或手机号后，提交收费时一并更新 PMS 业主用户信息。
- 住户资料更新与收费提交必须作为同一业务操作审计；收费失败时不得留下仅更新联系人、未生成收费记录的半成品状态。
- 收款方式继续使用旧网站已形成识别习惯的微信、支付宝、现金图标；新页面以彩色图标为主要识别线索，文字作为辅助说明。
- 选择房间后默认展开该房间的历史收费记录；记录按收费时间倒序，每页固定显示 `10` 条并提供分页。

## 2026-10-10 正式开发进度

- PMS“收费”正式入口新增公寓收费工作台；楼栋、房号使用 PMS 房产接口联动，数据范围由后端按当前账号所属管理处收窄。
- 收费台可补录/修改姓名与手机号；住户资料更新和多项目收费明细在同一数据库事务内提交，任一步失败都会整体回滚。
- 房间历史按收据汇总，按收费时间倒序并固定 `10` 条分页；微信、支付宝、现金沿用旧系统图标，支持 60–72mm 热敏小票预览。

- 旧订单转换脚本为 `tools/apartment-migration/prepare_apartment_fee_import.py`：只接收地址报告中 `matched` 且有唯一 `house_id` 的记录，一张旧订单拆为多条费用明细，共用原账单号，使用 `apartment:order:<订单ID>:<费用代码>` 幂等。

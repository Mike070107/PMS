# 公寓物业系统并入 PMS

## 已确认范围

- 公寓业务并入 PMS，后续账号、角色和权限全部在 PMS 重新分配，不迁移旧系统账号与权限。
- PMS 的社区、楼栋、房产和房间编号是主数据；旧系统地址只作为业务来源和历史快照。
- 旧地址中的姓名、手机号仅在房产唯一匹配后合并；冲突数据必须进入人工确认，不覆盖 PMS 已有资料。
- 旧系统小区编号 `5`（数据库现名“吴泾老家”）固定对应 PMS“馨香臣寓吴泾店”（社区 ID `20`）。该小区属于“吴泾一村管理处”（管理处 ID `7`），但不能因此匹配到 PMS“吴泾一村”（社区 ID `19`），也不得匹配到“吴泾新村”或 `5530` 弄。

## 2026-10-10 数据盘点

- 旧地址 `1,649` 条，旧收费订单 `5,438` 条。
- 按 PMS 社区 ID、楼栋号、房间号严格匹配：`277` 条唯一匹配，`1,372` 条暂未匹配。
- 馨香臣寓颛桥店：`277/283` 条唯一匹配，剩余 `6` 条待核对。
- 旧小区编号 `5`：`823` 条全部限定在 PMS“馨香臣寓吴泾店”内；没有一条落到 PMS“吴泾一村”或“吴泾新村”。
- PMS“馨香臣寓吴泾店”当前有 `0` 条房产，因此这 `823` 条暂时都不能绑定 PMS 房产。需先在该小区下建立并确认正式楼栋、房间，再按 PMS 房间号迁移。

管理处只是数据归属层级，不参与房间匹配。匹配键固定使用 PMS 小区 ID、楼栋号和房间号，避免同一管理处下不同小区发生串户。

## 迁移约束

1. 先生成只读映射报告，不直接更新 PMS。
2. 唯一匹配才能进入联系人合并：空白字段可补齐，完全相同跳过，姓名或手机号冲突进入人工确认。
3. 收费订单保留旧地址文本、旧地址 ID 和旧订单 ID，写入时使用幂等键，重复执行不得重复入账。
4. 未匹配地址、范围房号和冲突联系人不得自动选择“最像”的 PMS 房产。
5. 导入前备份，先在测试环境全量演练；对账通过后另行取得生产写入授权。

## 验收口径

- 社区映射中不存在旧小区 5 指向 PMS 社区 19、社区 13 或 `5530` 弄的记录。
- 旧小区 5 的目标必须是 PMS 社区 20，且该社区归属吴泾一村管理处（管理处 ID 7）。
- 地址总数、订单总数、订单金额和红冲/负数记录迁移前后可对账。
- 每条导入订单可追溯到旧订单 ID 和旧地址快照。
- 账号权限来自 PMS，不创建或复用旧系统用户凭据。

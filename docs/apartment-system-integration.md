## 颛桥店历史订单补齐与「汇总/明细分开」（2026-10-11，用户当次授权「颛桥店也导入」）

### 口径

用户原话：「停车结算/安乐村 汇总是汇总，明细就是明细」。落到实现：

- 旧库「停车结算」这个「地址」不是一间房，是按月结算的台账，备注里写着「月租车 80 辆 2400，临时车 100 辆 250，合计 2650」。
- 用户 2026-10-11 追加确认：**「订单数 11 笔就是对应 11 笔退费明细」**。所以一张单就是一笔明细，一对一落一行：
  - **不合并**：11 张单落 11 行，各自保留自己的收据号。曾把费用项命名为「停车结算汇总」，等于把明细叫成汇总，已改回「停车结算」——「汇总」指的是备注里那段车辆拆分，不是这一行本身。
  - **不拆**：不能照备注里的车辆拆分编造每辆车的明细行，也不填数量和单价（旧库那里的「停车费月数」写的是 16、19 这种台账流水，不是真实月数，一旦拿来算单价就是假数据）。原始拆分原样留在备注里。
- **各户明细照旧**：普通房间的停车费仍是 `parking`／「停车费」，带月数、单价、车牌。
- 单独给 `parking_settle` 一个费用代码只为了在报表里和各户停车费分开，不是把它当汇总行：`停车费 84,385.00 / 408 笔`、`停车结算 −21,305.00 / 11 笔`。
- 这 11 行严格说是 10 笔退费 + 1 笔收款（202607 那张 +2,035.00 当月又原额退掉）。
- 安全阀：汇总单的实收总额必须等于明细列合计，不一致就进拒绝清单，不猜（`test_汇总总额与明细合计不符时拒绝而不是猜`）。

### 顺带修正的退费口径

旧库记退费有两种写法：`红冲=1`，和直接记一笔负数的【退费】单（颛桥 88 笔，`红冲` 仍是 0）。两者是同一件事，统一按 `refunded` 落库。对账的退款额是按金额正负算的（`SUM(CASE WHEN amount_cents < 0 …)`），状态改了不会重复计。改前生产只有 `30` 条 refunded，改后 `235` 条。

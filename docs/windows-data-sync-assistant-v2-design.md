# PMS Windows 数据同步助手 V2 设计

> 状态：开发基线  
> 日期：2026-09-30  
> 目标：一台电脑只安装一个助手，同时承载零到多个本地数据连接；用户只做一次 PMS 配对，参数能检测就不输入、能保存就长期保存。

## 1. 产品模型

V2 不再把“一个程序目录”当成一个代理。系统分为两层：

```text
Windows 主机（一次安装、一次配对）
├─ 旧发卡数据库连接
├─ 停车 SQL Server 连接（可含 parking1 / parking2）
├─ 门禁 MDB 连接（可含 MjSystem / iCCard）
├─ USB 发卡器连接（可有多个读卡器）
└─ 后续新增的数据服务连接
```

- **主机**：一台 Windows 电脑的稳定身份。主机 ID 与连接密钥只生成一次，正常升级不变化。
- **连接**：主机能访问的一项数据服务或硬件能力。每项连接有独立名称、类型、参数、密钥、读写权限和健康状态。
- **任务**：PMS 下发的查询或写入动作，必须指定连接 ID 或明确的能力选择规则，不能再仅按代理类型猜测目标。

## 2. 部署与数据位置

### 2.1 固定目录

- 程序：`C:\Program Files\PMS Data Sync Assistant\`
- 持久配置：`C:\ProgramData\PMS\DataSyncAssistant\`
- 日志：`C:\ProgramData\PMS\DataSyncAssistant\logs\`
- 更新暂存：`C:\ProgramData\PMS\DataSyncAssistant\updates\`

升级只替换程序目录。配置、数据库密码、PMS 主机密钥和连接状态不放在 EXE 旁边，因此新增功能或替换版本不会要求重填。

### 2.2 保存内容

| 文件 | 内容 | 保护方式 |
|---|---|---|
| `host.json` | 主机 ID、电脑名称、PMS 地址、版本 | 非敏感；限制普通用户修改 |
| `connections.json` | 连接 ID、类型、显示名称、非敏感参数、开关 | 非敏感；原子写入并保留上一版 |
| `secrets.dat` | PMS 主机密钥、各连接数据库密码/API Secret | DPAPI LocalMachine；仅 SYSTEM/管理员可读 |
| `health.json` | 最近心跳、连接测试结果、错误编号 | 不含密码和完整连接串 |

数据库密码、一次性配对密钥和 API Secret 不写日志、不回显、不进入 Git。保存后的密码输入框只显示“已保存”；留空代表保持不变，另提供明确的“更换”操作。

## 3. Windows 进程结构

- 一个 Windows 服务：`PmsDataSyncAssistant`。
- 一个托盘进程：只显示一个图标，汇总整台电脑所有连接的状态。
- 一个设置界面：负责配对、连接管理、诊断和更新，不承担持续同步。
- 服务启动后加载所有启用连接，以统一调度器轮询 PMS；某个连接失败不能阻塞其他连接。

不再按旧库、停车、门禁分别安装多个 Windows 服务，也不再要求复制多个程序目录。

## 4. 简化后的用户流程

### 4.1 首次安装

1. 双击安装包。
2. 助手自动填写电脑名称并检测本机可见的 SQL Server、MDB 和 PC/SC 读卡器。
3. 用户只粘贴 PMS 网页生成的一项“电脑连接码”。
4. 助手保存主机身份并自动安装后台服务。
5. 首页显示“PMS 已连接”，随后引导添加数据连接。

不显示代理 ID、服务名、命令行、配置文件路径和内部 API 地址。

### 4.2 添加连接

三步完成：

1. **选择类型**：停车系统、旧发卡数据库、门禁系统、USB 发卡器。
2. **确认检测结果**：助手带出已知默认值并自动检测；只有检测不到的字段才要求输入。
3. **测试并保存**：显示具体检查项，例如“SQL Server 可达、parking1 可读、存储过程可用”。通过后保存并立即生效。

同一电脑可以添加多个同类型连接，例如两个 SQL Server 或两个 USB 发卡器。显示名称由系统建议，用户可以修改。

### 4.3 日常首页

```text
PMS 数据同步助手                         PMS 已连接
本机：物业办公室-01                       后台服务运行中

数据连接（4）                                  ＋ 添加连接
┌ 停车系统 · 枫桦景苑一期/二期 ───────────────┐
│ 已连接  可查询  写入待验收       测试  编辑  │
└──────────────────────────────────────────────┘
┌ USB 发卡器 · ACR122U ───────────────────────┐
│ 设备在线  等待任务                 测试蜂鸣  │
└──────────────────────────────────────────────┘

最近活动：10:32 查询车牌成功 · 10:28 PMS 心跳正常
```

状态色只使用：绿色正常、品牌色处理中、灰色未启用、红色需要处理。图标使用 SVG/系统矢量图标，不使用 emoji。

## 5. 发卡器与远程网页操作

发卡器作为一种硬件连接，由插着发卡器的电脑助手管理。网页操作电脑可以是另一台电脑：

```text
网页操作电脑 ──提交发卡任务──► PMS
                                  │
                                  ▼
                    指定的发卡工作站连接
                                  │
                                  ▼
                     ACR122U 写卡并回传结果
```

必须满足以下约束：

- 网页选择明确的发卡工作站，默认使用上次成功的工作站，不显示内部 ID。
- 页面显示工作站名称、在线状态、读卡器状态和“请在该工作站放卡”。
- 同一工作站一次只处理一张卡；任务有租约、超时和取消。
- 写卡前再次核对房号、卡号和目标权限；完成后回传读卡校验结果。
- 如果操作员与发卡器不在同一位置，现场仍需有人放卡和取卡。系统不能远程解决物理放卡动作。

因此技术上两台电脑可以不同；物业办公室实际使用时，建议网页默认选择操作员身边的发卡工作站，减少沟通成本。

## 6. PMS 服务端模型

### 6.1 主机表 `data_sync_hosts`

- `id`, `tenant_id`, `host_key`, `name`
- `token_hash`, `enabled`, `version`
- `last_seen_at`, `status`, `created_by`, `updated_by`

### 6.2 连接表 `data_sync_connections`

- `id`, `host_id`, `connection_key`, `type`, `name`
- `capabilities`, `enabled`, `readiness`
- `last_test_at`, `last_error_code`, `last_error_message`
- `config_fingerprint`（用于识别重复迁移，不保存密码）

### 6.3 任务表

任务必须记录 `connection_id`、幂等键、租约主机、尝试次数和结果。查询与写入分开授权；数据库能连接不等于允许写入。

## 7. 任务路由

1. 用户明确选择的工作站/连接优先。
2. 未明确选择时，只在同租户、在线、具备所需能力且健康检查通过的连接中选择。
3. 多个候选时按最近成功、当前负载和配置优先级选择，并把实际目标展示给用户。
4. 写入任务不得因为首选连接离线而静默改投另一数据库；需要用户确认或业务预先配置的主备规则。
5. 连接禁用、密钥轮换和删除都不改变历史审计记录。

## 8. 旧版迁移

首次启动 V2 时扫描用户选择的旧目录或已知旧服务路径：

- 每个有效 `agent.config.json` 转换为一项连接。
- 同机 DPAPI LocalMachine 密文可以直接解密后重新写入统一 `secrets.dat`，无需用户重填。
- 按服务器、数据库和类型生成指纹，合并重复连接。
- 已被历史覆盖而不存在的旧代理密钥无法恢复，只对该主机做一次重新配对。
- 迁移完成前不删除旧目录；生成迁移报告并允许回退。

## 9. 更新机制

- 设置页显示当前版本和可用版本，一键更新。
- 更新器先下载/选择新版，校验哈希和签名，再停止唯一后台服务、备份程序、原子替换并重启。
- 界面持续显示“下载、校验、停止服务、替换、重启、验证”六个阶段。
- 任一步失败自动恢复旧程序并显示具体原因与错误编号。
- 更新绝不修改 `ProgramData` 中的配置和密钥。

## 10. 开发顺序与验收

### 阶段 A：主机与多连接基础

- 新配置存储、DPAPI 密钥字典、单服务多连接调度器。
- 新首页和添加连接向导。
- 一次配对、连接增删改查、独立测试。
- 旧配置只读迁移。

验收：同一电脑同时启用旧库与停车连接，两者心跳和查询互不影响；重启、升级后无需重填。

### 阶段 B：PMS 主机/连接模型和任务路由

- 服务端拆分主机与连接。
- 管理页面显示电脑、连接和能力。
- 停车查询、旧库历史查询改为按连接派发。

验收：两台电脑、四个连接在线时，每项任务都到达指定连接，离线和失败提示能定位到具体电脑与连接。

### 阶段 C：发卡工作站

- PC/SC 读卡器发现、选择和独占队列。
- 网页工作站选择、放卡提示、写后读回校验、取消和超时。

验收：网页电脑与发卡器电脑不同，仍能完成一张测试卡；重复点击不会重复写卡，错误工作站不会领到任务。

### 阶段 D：正式写入和自动更新

- 按连接分别开放数据库存储过程、住户资料和控制器写入；每项任务都执行并发校验、写后读回和操作审计。
- 完成签名校验、自动更新、失败回滚和诊断包。

验收：更新过程中强制制造下载失败、服务停止超时和启动失败，均能自动回滚；原配置和密码始终可用。

## 11. V2 完成标准

- 普通用户从全新电脑到首个连接可用，不需要 PowerShell或编辑文件。
- 一个电脑只有一个服务和一个托盘图标，可管理多个连接。
- 正常升级、增加功能、增加连接均不要求重新输入已有密钥或密码。
- 所有失败提示指出具体电脑、连接、字段/步骤和修复办法。
- 主机身份、连接身份、任务审计和升级版本均可追溯。

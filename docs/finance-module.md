# 财务记账模块

财务模块使用独立的 TypeORM 连接与 `finance_*` 数据表。正式环境应配置 `FINANCE_DB_NAME` 指向独立数据库；本地未配置时会复用主数据库连接，但仍与 PMS 业务表隔离。权限在服务端强制校验，仅租户管理员、平台管理员进入租户视角后，或姓名严格为“叶双”的当前租户员工可访问；普通角色权限无法放开该入口。

## 必需配置

```dotenv
# 正式环境使用独立数据库
FINANCE_DB_HOST=127.0.0.1
FINANCE_DB_PORT=5432
FINANCE_DB_USER=pms_finance
FINANCE_DB_PASS=replace-me
FINANCE_DB_NAME=pms_finance
FINANCE_DB_SYNCHRONIZE=false

# 用于 AES-256-GCM 加密邮箱授权码，至少 16 个字符；生产环境应由密钥管理服务生成
FINANCE_SECRET_KEY=replace-with-a-long-random-secret
```

首次启用新库时按现有数据库发布流程创建结构，不应长期打开 `FINANCE_DB_SYNCHRONIZE`。邮箱地址与 IMAP 授权码只通过“财务记账 → 邮箱设置”录入，授权码不写入源码、环境模板、日志或接口响应。

## QQ 邮箱同步

- 固定使用 `imap.qq.com:993` 与 TLS，仅以只读方式打开 `INBOX`。
- 首次同步最近 7 天；之后按 `UIDVALIDITY + UID` 增量拉取。
- QQ 邮箱同步仅接收 PDF 附件，按 SHA-256 去重；后台手工上传仍支持 PDF、OFD、XML、JPG、PNG、WebP、ZIP。
- 同步不会标记已读、移动或删除邮件；页面“丢弃”仅改变财务收件箱状态，可恢复。
- 金额或日期相同只用于候选排序，不自动建立关联；用户确认后才匹配流水。

## 当前交付边界

已实现项目/子项目、项目附件与流水凭证的拖拽/截图粘贴、收支流水、发票收件箱、QQ 邮箱连接与每 5 分钟自动增量同步、发票人工匹配/恢复丢弃、报销申请与付款完成。

## 会计核算内核

- 每个租户只有一个独立账套，默认执行《小企业会计准则》，主管税务机关档案为上海。一级科目和报表映射由系统维护，不能改名、停用或删除；企业只能新增明细科目。上级科目存在明细后自动停止直接记账。
- 期初余额通过系统 Excel 模板导入。保存前同时校验借贷试算平衡和“资产 = 负债 + 所有者权益”；错误显示到具体 Excel 行，校验不通过不会覆盖已有期初数据。
- 新增流水自动产生草稿凭证；“同步业务单据”可为上线前已有流水补建草稿且按来源去重。凭证必须借贷平衡，可人工修改、复核、过账、取消过账；每次状态和内容变更写入独立审计表。只有已过账凭证进入科目余额表和财务报表。
- 会计工作台提供标准科目表、期初余额、智能凭证、科目余额表、资产负债表、利润表和月末结账入口。月末可按已过账损益余额生成一张待复核的损益结转凭证。结账前强制检查未过账凭证和资产负债表平衡；结账后锁定当期，反结账必须从最新已结期间倒序进行。
- 内部账按月核算和结账。上海新电子税局公开口径原则上按季度和年度报送，并根据企业“财务会计制度及核算软件备案报告”自动带出报送种类；系统保存 `shanghai_small_enterprise` 报送档案，不把旧的月报口径写死成企业实际申报频率。
- 现金流量表、附注、上海税务文件接口导出需要在现金流项目映射和企业备案小类确认后启用，不能从未分类的银行流水直接生成并声称可申报。

相关结构由 `1792972800000-AccountingCore.ts` 创建。正式发布必须先执行独立财务库迁移，再启动包含新实体的 API。

## 发票识别、税务数字账户导入与验真

- XML 使用结构化标签提取；OFD 解包后读取内部 XML；文本型 PDF 提取文字层。扫描 PDF 和 JPG/PNG/WebP 图片会调用租户当前配置的 OpenAI 兼容视觉模型，模型未配置或不支持图片时保留原件并明确标记“识别失败”，不会伪造字段。
- 统一保存发票代码、号码、日期、价税合计、税额、购销双方名称与税号，并记录识别状态、识别来源、置信度及原始响应。重复判断优先使用发票代码与号码，文件本身另按 SHA-256 去重。
- Web 端“税务数字账户导入”接收全量发票查询导出的 XLSX、XLS、CSV。相同发票再次导入会补全字段及查验结果，导入批次记录新增、更新、失败数量和具体错误行。
- 验真状态为未验真、查验中、验真通过、验真不通过、查验异常；当前状态保存在发票主记录，每次结果另写 `finance_invoice_verifications` 历史表。税务数字账户中的查验结果以 `tax-account-import` 来源入账。
- `InvoiceVerificationProvider` 是统一验真接口契约。后续接入乐企或合规第三方时实现该接口并注册 provider；业务表、页面和历史记录不绑定具体服务商。

结构升级使用独立财务数据源执行：

```bash
pnpm --filter @pms/api finance:migration:run
```

执行前仍应按发布流程备份财务库并审阅 `src/finance-migrations` 中待运行 SQL；不要用 `FINANCE_DB_SYNCHRONIZE=true` 替代正式迁移。

## Web 端凭证预览

- 在凭证拖拽区黏贴或上传图片后，图片必须直接替换提示内容并显示在虚线框内部，不能另起一行放到虚线框下方；缩略图使用 `object-fit: contain`，不得裁掉凭证内容。
- 点击缩略图打开大图预览；删除按钮常驻可见。非图片凭证继续显示文件卡片，不能伪装成损坏图片。
- 浏览器本地预览地址只用于当前编辑会话，保存前必须从接口载荷中移除，并在删除、取消、保存或页面卸载时释放。
- 验收需覆盖黏贴图片、拖拽图片、点击预览、删除、取消后重新打开，以及 360px 窄屏无横向溢出。

## 员工小程序财务页

- 财务页使用独立的 `finance-*` 样式命名，避免与小程序全局 `.hero`、`.sheet` 等组件互相覆盖。
- 原生 `button` 必须显式设置 `width`、`margin`、布局与行高；“记一笔”和“按住说话”均保持整行居中，语音文案禁止换行。
- 页面提供总览、流水、项目、PDF 发票和报销五个移动端工作区。所有网格轨道使用 `minmax(0, 1fr)`，弹层内容独立滚动，底部操作区包含安全区间距。
- 验收先跑员工端 TypeScript 检查和微信开发者工具真实预览编译，再检查 360px 窄屏无横向溢出、弹层能滚到底、主操作按钮始终可见。

# 抄表模块（拍照识别 + 档案 + 记账）

2026-10-30 首版。解决的是「物业人员到现场，拍一张水表/电表照片，把读数准确记下来，
事后能拿原图核对，并按表出应收、登记收款」这一条链。

- 员工端小程序：`抄表 → 选表/扫码 → 拍照 → 自动识别 → 对照原图确认 → 提交`
- 管理后台：`收费业务 → 抄表管理`，三档：抄表记录（复核）、仪表档案、账单记账
- 识别服务：自托管 OCR 边车（`tools/meter-ocr-service`），不依赖外部账号、不按次付费

## 1. 为什么识别结果不直接入账

照片 OCR 的准确率再高，也会有反光、污渍、小数点看不清的时候。这个模块把「识别」和「记账」
严格分开：

1. OCR 只负责把可能读数回填到输入框；
2. 抄表员必须对着原图确认，才能提交；
3. 服务端按档案里的「整数位/小数位」解释数字（电表 `02241888` → `22418.88`），
   不靠模型猜小数点；
4. 原图、OCR 原文与置信度、人工确认值三者都留在同一条记录里；
5. 后台复核页随时能看原图、改数（只能改最近一次）、作废并联动账单。

因此「识别率」影响的是录入速度，不是账的准确性。两张样图的实测结果见第 6 节。

## 2. 仪表档案字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 表号 `meterNo` | 是 | 表身钢印号/出厂编号/条码号；同公司同类型内唯一 |
| 表类型 `meterType` | 是 | 水/电/燃气/热量；决定默认单位和位数 |
| 名称 `name` | 否 | 如「301室电表」「1号楼总表」 |
| 口径/规格 `spec` | 否 | DN20、3×220/380V 1.5(6)A |
| 厂家 / 型号 | 否 | 报修、换表时用 |
| 倍率 `multiplier` | 否 | 经互感器的电表、大口径水表；默认 1 |
| 整数位 `integerDigits` | 是 | 电表常见 6；水表常见 5。**填错读数会差 10 倍/100 倍** |
| 小数位 `decimalDigits` | 是 | 电表常见 2；机械水表常见 0 |
| 计量单位 `unit` | 是 | m³ / kWh / GJ |
| 所属小区 `communityId` | 否 | 用于数据范围和筛选 |
| 安装地点 `installAddress` | 否 | 楼道水表井、负一层电表箱 3 号柜等 |
| 经纬度 `latitude/longitude` | 否 | 存 GCJ-02；员工拍照时自动记录，后台可浏览器定位/手填 |
| 使用人 `ownerName` | 否 | 住户/商户/责任人 |
| 使用人电话 `ownerPhone` | 否 | 现场联系、欠费催缴 |
| 单价 `unitPriceCents` | 否 | 分/单位；4.2 元/m³ 存 420 |
| 自动生成应收 `billingEnabled` | 是 | 关掉只抄表留痕，不出账单 |
| 期初底数/日期 | 否 | 第一次抄表用它算用量；不填则第一次只记读数 |
| 状态 `status` | 是 | 启用/停用（停用保留历史，不能继续抄） |
| 表具照片 `photoUrl` | 否 | 铭牌/表位照片，支持点击、拖拽、Ctrl+V |
| 备注 `remark` | 否 | 换表、井盖位置等 |

数据模型里还预留了 `houseId`（关联具体房号），后台首版用「小区 + 安装地点 + 使用人」表达，
后续要做房号选择器时不需要改表。

## 3. 抄表记录与账单字段

**抄表记录**：表号快照、本次读数、上次读数、用量（已乘倍率）、拍照时间、入库时间、来源
（拍照/人工/导入）、原图 objectKey/URL/宽高、OCR 服务商/置信度/原文/识别表号、异常标记、
GPS、抄表人、备注、复核人/复核时间、幂等键。

异常标记（只提醒、不阻断）：`识别置信度低`、`表号不一致`、`表计归零`、`本次零用量`、
`用量突增`、`补录历史时间`、`无现场定位`、`未留原图`。

**账单**：账期 YYYY-MM、用量、单价快照、金额、人工调整、应收、已收、状态
（待收/部分收款/已结清/已作废）、到期日、收款时间、收款方式、票据号、备注。
金额全部用「分」存整数，避免 `0.65 × 153.2` 的浮点尾差。

## 4. 权限

- 后台页 `meters`：查看 / 编辑（建档、补录、复核改数、收款、调整）/ 删除（作废未收账单）
- 小程序入口 `app:meters`：查看（档案和历史）/ 编辑（拍照提交读数）
- 员工端**不能**收款、不能改档案、不能修历史读数；这些只给后台 `meters` 页
- 数据范围沿用员工工作范围：只能看/抄自己管理处的表；公司级角色看全部
- 存量公司：开通了「物业费」或「前台收费」的，`meters` 自动可用；平台也可在
  「物业公司 → 可用页面」里单独关掉
- 角色授权：后台「业务角色」里给对应角色勾 `抄表管理` 和 `抄表`

## 6. 识别服务与实测

架构：小程序上传原图 → API 读对象存储 → `MeterOcrService` 调本机 OCR 边车
（`tools/meter-ocr-service`，RapidOCR/ONNX）→ 返回文字框 → 纯函数解析读数/表号 →
回填输入框。边车不可用时，若租户配置了多模态大模型则兜底，再不行就让用户手工输入。

两张现场照片（1536×2730）实测：

| 照片 | OCR 原文（节选） | 解析 |
| --- | --- | --- |
| 水表 | `GB/T778-2018`、`Q3=m3/hR=80`、`02405m` | `02405`，置信度 81；不把 `7782018` 当表号 |
| 电表 | `0224 1888`、`20054564`、`6400imp/kWh` | `22418.88`（6 位整数 + 2 位小数），置信度 96；表号 `20054564` 与档案匹配 |

关键解析规则（`meter-ocr.util.ts`）：

- 同一行的框按 x 拼起来，`0224` + `1888` → `02241888`；
- 位数与档案一致的候选优先；同时用框的高度/宽度区分「大号读数」和「小号铭牌表号」；
- 铭牌行（GB/T、DTS、Hz、年、制、imp 等）扣分，不参与读数；
- 表号只从 6 位以上、与读数不同、且不在读数框里的数字里找；没有标签/分数不够就返回空，
  不硬猜；
- 两个分数接近的读数会标 `needsReview`，不自动选。

回归测试：`pnpm --filter @pms/api test:meters`（8 个解析/计费用例 + 3 个真实 SQL/事务用例）。

## 8. 已知边界与下一版

- 一张抄表记录保留一张原图；多角度/多表同框暂不支持；
- 只做「单价 × 用量 + 人工调整」，没有阶梯价、公摊、总表-分表损耗分摊；
- 未做离线队列：断网提交失败时页面保留原图、读数和幂等键，可原地重试；离开页面后需重拍；
- 未接物业费 `fee_bills`：水电应收独立成账，避免和物业费红冲体系混用；需要对账时导出 Excel；
- 表号 OCR 对喷码/磨损字不保证，后台仍以人工建档的表号为准；
- 仪表档案暂未做批量导入/房号选择器，表多的小区建议下一版加 CSV 导入。

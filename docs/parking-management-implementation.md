> 来源：`docs/parking-management-design.md` 2026-09-29 调研结论  
> 页面：`apps/admin-web/src/pages/ParkingManagementPage.tsx`  
> 原则：未经受控验证的外部写入不伪造为“已接通”。

## 2026-09-29 真实查询链路

- PMS 新增租户隔离的短期停车查询任务；管理员输入至少 2 个字符后，在线停车网关领取任务并回报结果。
- Windows 数据同步助手 0.4.0 同时查询 `parking1`、`parking2` 的 `Car_Issue`，只执行参数化 `SELECT TOP 50 ... WITH (NOLOCK)`，不调用写入存储过程。
- 查询兼容房号斜杠/横线形式，结果保留真实数据库列名；网页优先识别并紧凑展示车牌、房号、住户、电话、车位和统一到期日，其他字段可展开核对。
- 旧版 0.3.0 只支持数据库探测，网页必须显示“需升级助手”并禁用查询；0.4.0 在线且上报 `parkingDbRead` 后才显示“查询已就绪”。
- 任务租约 90 秒，失败最多重试 3 次；网页轮询约 72 秒后给出明确超时提示。每个库最多 50 条，接口总计最多接收 100 条、每条最多 60 个标量字段。
- 浏览器验收覆盖：0.3.0 升级提示与禁用态；0.4.0 就绪态；以 `228/5/301` 查询后展示车牌卡片和可展开的原始字段。
- 仍未开放登记、续期、换牌、注销或设备下发；页面“写入未开放”是能力边界，不是可点击按钮。
- 发布复核发现：为验证 0.3/0.4 两种状态而写在真实页面组件内的样例值，虽然生产不渲染，仍会进入生产 JS。根因是“开发路由受保护”不等于它传入组件的常量也会被剔除。已把全部验收数据迁到仅在 `import.meta.env.DEV` 下动态加载的独立页面；验收除检查界面不显示外，还必须扫描生产产物不存在样例房号、住户、车牌和车位。

## 2026-09-29 业务规则修正

- 现象：首版页面按原调研稿将四个授权目标分别显示到期日，住户搜索卡占用空间过大却没有展示车牌和明确的车库类型。
- 已确认规则：每辆车只有一个统一到期日；四个停车区只独立管理是否开通、车位、收费方式和同步状态。续期提供 1/2/3/6/12 个月快捷选项，业主车与租户车分别配置月单价和年付优惠价，并可即时验算。
- 页面处理：“续期”调整为默认首个标签；住户搜索卡缩小留白并补车牌、车库类型和车位编号，没有车位则不显示车位行。
- 验收：无任何按车库编辑到期日的入口；切换五个快捷月数时续期后日期和金额同步更新；12 个月使用年付价并显示节省金额；收费规则和缴费验算弹窗均可操作。

## 上线前硬缺口

1. 按调研文档 18.1 用测试车牌验证本地停车存储过程、设备映射和控制器回执。
2. 按 18.2 为 PMS 创建最小权限德立云 AccessKey，先做只读契约验证，再测试新增、授权、续期和取消。
3. 由物业确认 18.3 的收费、容量、审批和换车继承规则。
4. 建立数据表、API、本地停车网关、目标级幂等任务、审计和每日对账作业。

## Windows 本地停车网关

- 复用 `tools/access-card-agent` 的“PMS 数据同步助手”，新增 `parking_gateway` 部署身份，不另造一套 Windows 程序。
- 可在图形界面配置 SQL Server、`parking1`、`parking2` 和数据库用户；密码使用 Windows DPAPI `LocalMachine` 加密保存。
- `--parking-probe` 对两个数据库执行只读探测：统计 `Car_Issue` / `Car_Download`，并检查已调研存储过程是否存在。
- API 支持注册 `parking_gateway` 并接收心跳。在专用停车任务队列落地前，停车网关只获得空任务，不会误领门禁旧库任务。
- 能力上报为 `parkingDbRead=true` / `parkingDbWrite=false`。登记、续期、换牌、注销和设备下载仍保持关闭，必须在真库只读探测与存储过程参数验收后逐项开放。

# 生产数据边界（2026-09-29 纠正）

- 生产 `/parking` 禁止使用预览住户、车牌、车位、到期日或收费金额；真实接口未接通时必须显示明确空状态。
- 设计评审页与生产页使用不同入口和不同组件。预览组件只允许由 `import.meta.env.DEV` 动态加载，生产构建必须检查不包含示例房号、车牌和车位。
- 发布验收除检查路由与样式外，还要扫描生产资源，断言示例值不存在；能打开页面不等于已接入真实业务数据。
- 同一网关重新注册会保留多条记录；状态选择必须优先使用持续心跳且心跳时间最新的记录，不能按最早 ID 取第一条。验收需覆盖“旧记录离线、新记录在线”的重复注册场景。

## 网关安装后的状态刷新（2026-09-29）

- 现象：管理员先打开停车页，再安装或升级 Windows 助手，助手已经持续向生产服务发送 0.4.0 心跳，原页面仍停留在“未连接”。
- 已证实原因：页面只在首次进入和手动点击“重新检测”时读取一次状态；安装过程发生在页面打开之后，旧状态不会自行失效。同时本机 `127.0.0.1:4187` 是临时开发服务，不是生产入口，服务停止后不能用于判断生产连接状态。
- 正确处理：生产停车页每 5 秒静默刷新一次网关状态，窗口重新获得焦点或标签重新可见时立即刷新；后台轮询失败不反复弹提示，用户主动检测失败仍显示具体错误。正式使用入口固定为 `https://prsznh.cn/parking`。
- 验收：先让页面得到离线状态，再启动 0.4.0 网关，不手动刷新页面也应在 5 秒左右变为“已连接 / 查询已就绪”；生产端还要下发一次只读查询并确认被 0.4.0 网关领取、完成，而不是只看心跳字段。
- 状态标签不得只显示灰色数据库名：灰色容易被理解为未连接。真实查询就绪时，`parking1`、`parking2` 分别显示绿色勾选和“已连接”；未就绪时明确写“未验证”，不再让用户仅凭颜色猜测含义。

## 旧库住户联查与 PMS 关联（2026-09-29）

- 现场只读抽样确认 `Car_Issue` 真实字段包括 `P_plate`、`Owner_ID`、`Car_Lei`、`End_Time`、`P_Spaces` 等；住户姓名、房号、电话不在车辆表中。0.4.0 只查 `Car_Issue`，所以按车牌虽然能取得车辆，却无法展示住户；按姓名或房号也无法反查车辆。
- 生产 PMS 当前有 7,878 个用户、8,583 套房屋，但 `parking_vehicles` 为 0 条，因此此前没有停车车辆到 PMS 用户的现成关联。不能把 `Owner_ID` 直接当 PMS 用户 ID。
- 0.4.1 通过 `Car_Issue.Owner_ID` 优先使用数据库外键、其次按旧库元数据识别住户主表，参数化联查住户字段；API 再按规范化手机号与同租户 PMS 用户精确匹配。只有精确匹配才显示“已关联 PMS”，未匹配必须明确显示，禁止按姓名模糊绑定。
- `Car_Lei` 是数值型旧库车辆类别，现场尚未确认其枚举含义。原值可以显示为“旧库车辆类型 N”，但未经字段字典或样本核对不得擅自翻译成业主车、租户车或亲情车；住户主表若返回明确文本身份，才按文本展示。
- 页面数据库名称对用户显示为“枫桦景苑一期 / 枫桦景苑二期”，技术库名仅保留在原始字段与诊断信息中。
- 验收：安装 0.4.1 后，使用同一已知车牌和房号分别查询，二者应返回同一车辆并带住户主表字段；有手机号精确命中的记录显示 PMS 用户，无法精确命中的记录显示“尚未关联”，不能静默挂错住户。

## 车型、授权通道与设备生效规则（2026-09-29 旧库实查）

- 用户确认旧库实际字段 `Car_Brand`（口述曾写作 `Car_Beand`）保存车辆身份，已抽样看到住户车、租户车、亲情车、小区服务车和小区工作车。`Car_Lei` 不再冒充车辆身份。
- `P_note` 是业务备注，卡片应直接展示，不能只藏在原始字段中。`P_Effective` 与 `P_Download` 是按字符串位置记录各车辆进出通道的状态，位置编号就是通道号，不是库位或车位号。只有 `P_Download` 覆盖 `P_Effective` 的全部现行授权通道，授权才显示“设备下载成功 / 已生效”。两串不要求完全相等，因为下载记录可能包含当前授权以外的历史通道。
- 已用用户给出的 `沪BDQ8839` 锚定二期大车库：真实记录位于 `parking2`，`Car_Brand=住户车`、`P_note=地库91号`，`P_Effective` 授权通道号为 15/17/19/21，且下载记录完整覆盖。通道号 9/11/13 对应“二期地面车库”，15/17/19/21 对应“二期大车库”，两组都有则同时显示。
- 二期旧库通道号 23/25 是原人防车库通道，现已被德立云停车系统替代。这两个旧通道号一律忽略，不参与授权展示和下载生效判断；“二期人防车库”只根据德立云是否存在该车牌判断。德立云只读接口尚未接通前必须显示“以德立云为准”，不能沿用旧通道号或猜测权限。
- 2026-09-29 已增加德立云服务端只读适配器和独立状态卡。AccessKey 与 `commKey` 只保存在生产运行配置中，不进入源码、数据库、日志或前端；页面区分“未配置 / 配置待补充 / 只读已连接”，并显示版本、项目、签名或网络的具体失败原因。当前开放接口在 `/parking/findPunitInfo` 先校验停车 API `version`，账号详情尚未提供该值，因此不能把 AccessKey 已保存误报成数据已接通；写接口继续保持关闭。
- 四个操作项统一命名为“一期地面车库、二期地面车库、二期大车库、二期人防车库”。二期大车库是二期地面车库的子车库：只授权大车库时，车辆若未进入大车库，驶出二期地面通道可能按临时车计费；同时授权地面和大车库则不会产生该临时计费。页面按两个独立勾选项表达，不偷偷强制联动。
- 一期样本的通道号 5/7 显示“一期地面车库”。样本车牌最终更正为 `浙ABT3233` 后已在 `parking2` 查到：`Car_Brand=租户车`，`P_Effective` 与 `P_Download` 均为通道号 9/11/13，证明它只有二期地面车库授权、没有二期大车库授权，并且三个授权通道已经全部下载生效。
- 0.4.0 已能读取车辆表，所以页面不能因尚未升级住户联查而禁止全部查询；0.4.1 只作为按住户姓名、电话和房号联查的增强要求。

## 亲情车证明材料临时二维码

- 亲情车办公室不收费，门岗按优惠临时车计费；办公室新增亲情车必须先收证明材料。
- 办公室可从亲情车卡片生成 30 分钟有效的随机二维码。服务端仅保存 token 的 SHA-256，不保存原始 token；二维码限定当前租户和车牌，只能成功提交一次，过期后必须重新生成。
- 手机页允许拍照/选择 JPG、PNG、GIF、WebP、HEIC 或 PDF，限制 20MB，并继续使用服务端文件签名校验和私有对象存储。办公室弹窗每 2 秒更新“等待扫码 / 已打开 / 已上传”，上传完成后显示文件名。
- 验收覆盖：伪造格式、超大文件、过期 token、重复提交均拒绝；正常图片/PDF 提交后办公室状态自动变为已上传，材料通过私有文件代理可读取。

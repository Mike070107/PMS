## 3. 服务端配置与兼容性

配置项定义见`apps/api/.env.example`，实际读取见`apps/api/src/modules/fees/mis-fees.service.ts`。凭据只放服务端受控配置，不下发浏览器。

```dotenv
MIS_FEES_TENANT_ID=<明确绑定的PMS公司ID>
MIS_FEES_SERVER=wjwy.mis.shxwit.com
MIS_FEES_PORT=1533
MIS_FEES_DATABASE=MIS吴泾物业
MIS_FEES_USER=<授权的SQL登录名>
MIS_FEES_PASSWORD=<通过受控渠道配置>
MIS_FEES_TRUST_CERTIFICATE=true
MIS_FEES_LEGACY_TLS=true
```

上例表示本地成功连接采用的兼容选项；环境示例文件默认值仍为`false`。信任证书会跳过证书信任校验，旧TLS选项只用于此MIS连接，不得修改全局TLS设置。现实现使用`encrypt:true`、`tdsVersion:'7_3_B'`，旧TLS兼容为`minVersion:'TLSv1'`及`DEFAULT@SECLEVEL=0`。

连接池最多2条、空闲30秒；连接超时8秒、查询超时15秒。源库不可用时明确报错，不悄悄使用旧库或公寓流水替代。

新增`mssql`版本为`12.7.10`，依赖覆盖锁定Tedious `19.2.2`及Node20兼容的Azure依赖，记录在`pnpm-workspace.yaml`与`pnpm-lock.yaml`。生产运行时此前核实为Node `20.20.2`，本地成功测试使用Node24；**仍需在生产同版本运行时验证**。保留锁文件，不重新解析到要求Node22的驱动依赖。

SQL Server 2008查询使用`ROW_NUMBER()`分页、`+`拼接文本，不能使用`OFFSET/FETCH`或SQL `CONCAT()`。注意：PMS自己的PostgreSQL查询可以使用`CONCAT()`，不要把两个数据库方言混淆。

## 6. 查询金额与状态口径

状态优先顺序：有退款日期→退款；无退款且金额为负→负数调整；其余有收款日期→已收；其余→未收。

| 展示 | 当前计算规则 |
|---|---|
| 有效应缴 | 无退款日期且金额非负的源金额合计 |
| 已缴（未退款） | 有收款日期、无退款日期且金额非负 |
| 未缴金额 | 无收款日期、无退款日期且金额大于零 |
| 明细笔数 | 当前筛选条件命中的全部源记录，包括退款和负数调整 |
| 退款记录数 | 有退款日期的记录数，不推算退款净额 |

汇总针对全部筛选结果，不是当前分页。筛选“已收”后显示的是该筛选范围的金额，不能当作该户全部应缴。

退款存在正、负记录，当前没有建立完整退款配对及财务净额口径，不重复扣减、不推断实际退款额。有效应缴/已缴不是公寓收费台的有符号流水净收入算法。

源`money`先用`CONVERT(varchar(50),金额,2)`保留四位小数，再以十进制算法转整数分、半远离零舍入，不通过二进制浮点截断。汇总是源金额先求和再转分，明细逐行转分；存在小于一分的源金额时，显示明细之和可能与汇总有舍入差，需复核，不能强行改源金额。

账期和实收日期分别筛选。未来账期未缴不等于逾期；核对截至本月欠款应限制结束账期，当前页面默认全年账期，不应将全年未缴直接标为逾期欠费。未收记录不展示收款凭证和收款方式。

汇总与分页为同次请求中的两条SELECT，当前未使用数据库快照事务；并发收款时可能出现两者短暂不一致，应刷新核对，尚不提供财务结账级一致性保证。

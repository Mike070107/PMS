# PMS 架构改造路线

> 原则：保持现有 NestJS 模块化单体，按可独立发布的批次增强一致性、异步可靠性和权限粒度。

## 已完成：批次 1（工单一致性底座）

- 工单状态变化统一由 `work-order-state-machine.ts` 校验，业务动作和状态变化成对定义。
- 自动验收从硬编码改为租户设置 `auto_review_hours`，默认 48 小时，允许 1～720 小时。
- 全租户定时扫描按各租户自己的时限判断，并使用行锁防止自动验收和业主验收并发覆盖。
- 管理后台“系统设置”增加自动验收时限配置。
- 增加状态机和配置默认值的回归测试。

## 批次 2：事务事件与异步可靠性

1. 新增 `outbox_events` 表和 migration。
2. 工单、库存、采购的业务事务内同时写 Outbox 事件。
3. Worker 使用 Redis 队列发送微信/站内通知，支持重试、死信和幂等消费。
4. SLA 提醒、库存预警和报表聚合改为事件消费者；定时扫描仅作兜底。
5. 上线前先双写事件但不消费，核对事件完整性后再切换通知链路。

## 批次 3：资源级权限

1. 保留当前页面权限兼容层，新增稳定的资源动作，例如：
   - `work_order.assign`
   - `work_order.export`
   - `purchase.approve_manager`
   - `purchase.approve_purchaser`
   - `stock.adjust`
2. 页面映射到多个资源动作，API 不再直接依赖 `pageKey`。
3. 审批继续校验业务身份和流程节点，不能仅凭页面编辑权执行。
4. 增加仓库/库位数据范围；导出、库存调整、租户代操作作为敏感权限。
5. 存量角色自动迁移，页面权限兼容至少保留一个版本周期。

## 批次 4：租户隔离与审计加固

1. 请求入口统一建立租户上下文，Repository 查询统一注入 `tenant_id`。
2. 对核心业务表评估启用 PostgreSQL RLS，作为应用层过滤之外的第二道防线。
3. 工单、库存流水、审批记录禁止物理删除，只允许作废、冲销或更正。
4. 平台代操作、批量导出、库存调整和权限变更全部写独立审计事件。

## 每批上线门槛

- API 与管理后台类型检查通过。
- API、管理后台生产构建通过。
- 状态转换、金额/库存计算、权限拒绝路径有自动化测试。
- 多租户交叉访问验证返回 404/403，不能泄露对象是否存在。
- 迁移支持滚动发布和回滚；涉及异步消费时必须验证幂等。

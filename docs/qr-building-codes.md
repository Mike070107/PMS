# 楼栋报修码（小程序码）

一栋楼一张码，贴在单元门口/信箱。业主用**微信「扫一扫」**扫到就直接进业主端小程序的报修页，
小区/弄/号自动带出，只需补房号；没入驻的会被引导到入驻页，位置同样已经填好。

## 为什么是「小程序码」而不是普通二维码

普通二维码里存的是一条 URL，微信扫一扫只会打开网页，进不了小程序
（要跳小程序得走「扫普通链接二维码打开小程序」，需要域名备案 + 在公众平台配置规则）。
所以楼栋码改用 `wxacode.getUnlimited` 生成的**小程序码**：微信扫一扫原生识别，直接拉起小程序。

- `scene` = 码的 token（`nanoid(16)`，字母表 `A-Za-z0-9_-`，在微信允许的 32 位可见字符集内）
- `page` = 落地页，默认 `pages/repair-create/repair-create`（`WX_OWNER_QR_PAGE` 可改）
- 图片存对象存储的固定 key `qr-codes/wxa/<token>.png` —— **重新生成会覆盖同一个地址**，
  已经印出去、贴上墙的码不会失效

旧的普通二维码（`https://.../qr/<token>`）仍然能被小程序内的「扫码」按钮识别，
`GET /qr/:token` 也接受整条 URL，换码期间两种码并存不会断。

## 前提：小程序要有对应版本

`getUnlimited` 会校验落地页在目标版本里是否存在：

| `WX_OWNER_QR_ENV_VERSION` | 生成的码扫开的是 | 前提 |
|---|---|---|
| `release`（默认） | 正式版 | **业主端小程序必须已提审发布** |
| `trial` | 体验版 | 上传过体验版，且扫码人是体验成员 |
| `develop` | 开发版 | 上传过开发版，且扫码人是开发者 |

小程序还没发布时用 `trial` 先把流程跑通，**正式贴码前务必把该变量切回 `release`，
再在后台点一次「全部重新生成」**（后台列表里会给非 release 的码打橙色标签提醒）。

生成失败不会静默：错误原样落在 `qr_codes.last_error`，后台列表和批量补齐的结果弹窗里
直接显示微信返回的 `errcode/errmsg`，常见码还会附一句怎么改。

## 环境变量

```env
WX_OWNER_APPID=            # 业主端小程序凭据，生成小程序码复用登录那套
WX_OWNER_SECRET=
WX_OWNER_QR_PAGE=pages/repair-create/repair-create
WX_OWNER_QR_ENV_VERSION=release
```

两个 `WX_OWNER_QR_*` 都有默认值，不配也能跑。

## 码怎么来的

| 场景 | 行为 |
|---|---|
| 后台新建单个楼栋 | 建楼栋的同时建码并出图；微信/COS 挂了只记日志，**不影响楼栋创建** |
| 导入房产顺带建出的楼栋 | 只落码记录，不逐个调微信（避免导入把频率打爆），图片交给「批量补齐」 |
| 存量楼栋 | 后台「楼栋报修码」页点「批量补齐」 |

批量补齐分批跑：一次请求最多出 40 张，返回 `remaining`，前端循环调用并显示进度，
避免单个请求撞上 nginx 60s 读超时。前端也做了熔断——某一批一张都没成功就停，
不会拿着同一个配置错误空转。

## 后台操作（管理后台 → 基础档案 → 楼栋报修码）

1. 选小区（不选=全部），表格按楼栋列出，状态为「已生成 / 未生成 / 生成失败」
2. 「批量补齐」补所有未生成的；「全部重新生成」在换了落地页/版本后重画全部
3. 勾选要打印的楼栋 → 「预览并打印」→ A5 竖版预览，可选每页 1 / 2 / 4 张 → 打印
   - 浏览器打印设置：纸张 A5、方向纵向、边距「无」
   - 卡片上的虚线是裁切参考线，`border: dashed` 只在屏幕和纸上做视觉分隔

印刷文案（如 `枫桦景苑二期 228弄3号 · 扫码报修`）在**生成时就定好并落库**，
之后小区/楼栋改名不会自动改动已经印出去的码；要跟着改就点「重新生成」（会重算文案）。

## 扫码之后的分叉

落地页 `pages/repair-create/repair-create` 拿到 `scene` 后：

1. 静默 `wx.login` 换 token（扫码进来时本页就是启动页，不能假设首页已经登过）
2. `auth.me()` 看有没有入驻
   - 没入驻 / 被驳回 → `redirectTo` 入驻页，带上同一个 token
   - 已入驻 → 解析 token，带出小区/楼栋，直接填报修单

入驻页把码里的**弄/号拆开成两个可编辑输入框**（贴错码、扫了隔壁楼的情况能自己改）。
提交时若填了号，服务端会拿 `弄 + 号` 在该小区里重新匹配楼栋，
**匹配不到直接报错**（`XX小区没有「228弄3号」，请核对后重填`），不会静默丢掉或写脏数据。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/qr-codes/buildings?communityId=` | 楼栋码总览，含未生成的楼栋（后台列表 / 打印数据源） |
| POST | `/qr-codes` | 手工生成单张（小区码走这里；楼栋码已有则复用并补图） |
| POST | `/qr-codes/backfill-buildings` | 批量补齐，body: `{communityId?, limit?, force?}` |
| POST | `/qr-codes/regenerate` | 重新出图，body: `{ids?, buildingIds?, refreshCaption?}` |
| GET | `/qr/:token` | 公开解析，未登录可调；接受裸 token 或旧版整条 URL |

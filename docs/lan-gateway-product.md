# PMS 内网发布产品规格

> 状态：标准化控制面、动态路由、Windows 受管助手与微信扫码门禁已进入可部署版本；通配符 DNS/证书和旧用友链路切换仍属于一次性上线工作。现有“用友单应用 + 手工服务器配置”仅作为迁移来源，不能作为后续应用的运维方式。

## 当前实现（2026-10-02）

- PMS 已能创建代理设备、签发十分钟一次性安装码、自动分配端口、下发完整修订并显示五段发布进度；
- Windows 助手 1.1 可在新电脑用安装码注册，凭据由 DPAPI 保护，配置验签、内网探测、失败保留旧版、开机自启和自动更新均由图形界面完成；
- 腾讯云动态路由器按 Host 和数据库权限逐请求校验，不需要为每个新应用修改服务器代码、Nginx 或 systemd；
- 微信小程序扫码票据与目标应用绑定，授权用户确认后直接返回原应用域名，网关 Cookie 不会转发给内网站点；
- “在线”必须同时满足代理当前修订、内网探测、隧道进程和公网 HTTPS 健康检查，数据库保存不再冒充发布成功；
- 剩余上线动作是首次安装通配符 DNS/TLS/动态网关、执行数据库迁移并把现有用友域名从旧专属链路切换过去。完成后新增应用只操作 PMS。

## 产品目标

管理员在 PMS 后台填写应用名称、局域网地址、入口域名、代理设备和授权用户，点击一次“发布”。系统自动完成配置下发、局域网探测、公网路由、权限生效和状态验证。

新增、修改、停用任何内网应用时，运维人员不得：

- 登录腾讯云服务器；
- 新建或修改 Nginx、systemd、oauth2-proxy、FRP 配置；
- 修改、构建或发布程序代码；
- 登录 Cloudflare 新建子域名；
- 手工分配端口、复制 Tunnel Token 或执行 PowerShell。

只有首次部署网关基础设施、轮换平台密钥和处理主机故障属于平台运维。

## 标准产品组成

### PMS 控制台

PMS 是唯一配置源，保存以下数据：

- 代理设备：名称、安装位置、设备身份、版本、在线状态、能力和最后心跳；
- 内网应用：名称、一级子域名、局域网 URL、入口路径、所属代理、授权用户、会话期限；
- 发布期望：配置修订号、自动分配的网关端口、期望状态；
- 实际状态：代理已应用修订、内网探测、隧道连接、公网 HTTPS、最近错误和可查编号。

用户界面不暴露 FRP、Nginx、证书路径、Cloudflare Record ID 等实现细节。失败提示必须指出失败阶段和恢复动作。

### Windows 内网发布助手

助手是受管设备代理，不再要求用户在本机重复维护一份应用清单。

首次安装流程：

1. 管理员在 PMS 创建代理设备，获得十分钟有效、仅可使用一次的安装码；
2. 新电脑打开助手并输入安装码，助手生成本机设备密钥并完成注册；
3. 后台服务自动安装，连接凭据由 Windows DPAPI 保护；
4. 助手领取属于本设备的期望配置，验证内网 URL 后原子更新代理核心；
5. 助手持续上报修订号、代理进程、每条路由的探测结果和版本。

助手支持开机自启、断线退避重连、失败回滚、签名更新、日志导出和远程停用。用户只看“设备”“应用”“连接”三层状态，不接触 Token 文件和 TOML。

### 腾讯云动态网关

服务器只部署一次以下长期组件：

- `frps`：接收各局域网助手的 WSS 长连接，所有应用端口仅绑定 `127.0.0.1`；
- `pms-gateway-router`：按请求 Host 动态读取/缓存 PMS 发布配置，完成应用授权并转发到对应本机 FRP 端口；
- 通配符 Nginx 入口：统一处理 HTTP→HTTPS、TLS、WebSocket、上传限制和反向代理；
- 通配符证书自动续期：通过 Cloudflare DNS-01 续签，续签成功后校验并热加载。

新增应用只产生数据库配置修订，不生成新的服务器配置文件或服务进程。网关配置缓存必须支持主动失效与短周期自动刷新；PMS 暂时不可达时可继续使用最后一份已签名配置，但不能放大权限。

## DNS 与证书

Cloudflare 只承担 DNS 托管，不承担每个应用的 Tunnel 或 Access 配置。

一次性基础配置：

- 创建 DNS-only 的 `*.prsznh.cn` 兜底记录，指向当前腾讯云公网入口；
- 现有 `prsznh.cn`、`api`、`fire`、`gateway` 等显式记录继续优先于通配符；
- 通过最小权限 Cloudflare API Token 完成 DNS-01 通配符证书签发和自动续期；
- PMS 保留域名黑名单，禁止应用占用平台、邮件及基础设施域名。

完成这项一次性配置后，新建 `caiwu.prsznh.cn`、`warehouse.prsznh.cn` 等一级子域名不需要再进入 Cloudflare。

## 动态授权

- 访问未知或停用域名时，网关直接返回产品化 404/停用页，不把流量转发进内网；
- 未登录用户跳转到 PMS 微信扫码授权；
- 登录回调使用固定的中央回调地址，签名 state 记录目标应用，避免为每个子域名登记 OAuth 回调；
- 网关会话按应用隔离，令牌包含应用 slug、用户、到期时间和权限修订号；
- 每次建立新会话必须按数据库授权名单判断；取消授权后，现有会话按产品设置立即失效或在明确显示的期限内失效；
- 转发前剥离网关自己的认证 Cookie，不把平台令牌泄露给内网应用。

## 发布状态机

| 状态 | 含义 | 管理员动作 |
| --- | --- | --- |
| 草稿 | 尚未下发 | 补齐配置并发布 |
| 等待代理 | 目标电脑离线或未领取配置 | 启动指定电脑或更换代理 |
| 正在发布 | 代理正在探测和应用修订 | 无需操作，显示阶段进度 |
| 在线 | 内网、隧道、HTTPS、授权链路均通过 | 可打开应用 |
| 连接异常 | 已知阶段失败 | 按具体原因修复后重试 |
| 已停用 | 禁止建立新访问 | 可重新启用 |

数据库保存成功不能显示为“已发布”。只有代理应用了当前修订、网关已识别路由、外部 HTTPS 验证通过，状态才是“在线”。

## 自动端口与配置修订

- 网关端口由控制平面从保留范围内事务分配，端口是内部字段，前端和用户不填写；
- 同一应用修改内网 URL 时复用原端口，删除应用后延迟回收，避免旧连接串到新应用；
- 每次配置变化生成单调递增修订号；代理只接受比当前新的、签名有效的完整配置；
- 代理先写临时配置并做语法/连通性检查，再切换运行配置；失败继续运行上一修订并上报原因；
- PMS 对“期望修订”和“代理已应用修订”分别展示，禁止用最后心跳冒充配置成功。

## 安全基线

- 设备安装码一次性、短时有效，不包含长期 FRP Token；
- 每台代理拥有独立控制面凭据，可单独吊销和轮换；FRP 服务端插件在 `Login` 与 `NewProxy` 阶段再次核对设备令牌、应用 slug 和获配端口；
- 控制面下发响应带签名、有效期和设备受众；
- FRP 服务端拒绝客户端自行声明未获分配的代理名/端口，平台级 FRP 传输密钥本身不能绕过设备准入插件；
- Cloudflare、证书和平台主密钥只保存在服务器受限文件或密钥系统，不进入数据库响应、客户端包、日志和 Git；
- 操作日志记录创建人、授权变化、发布修订、设备领取和停用，不记录密钥正文。

## 标准管理员流程

1. 首次新增局域网：后台点击“添加代理设备”，在目标电脑安装助手并输入安装码；
2. 新增应用：选择代理设备，填写名称、`xxx.prsznh.cn`、内网 URL 和授权用户；
3. 点击“发布”，页面展示“下发 → 内网探测 → 隧道 → HTTPS → 授权”五段进度；
4. 通过后直接点击“打开应用”；失败时页面显示发生在哪一段、检测到什么、到哪里处理；
5. 后续修改、停用、换电脑和升级都在 PMS 完成，不登录服务器。

## 迁移路径

1. 保持现有 `caiwu.prsznh.cn` 链路运行，先上线设备注册、心跳和配置修订；
2. 用友电脑的助手自动导入旧配置并注册为受管设备，不更换内网 URL；
3. 部署通配符 DNS、证书和动态网关，以影子模式验证 Host 路由和授权；
4. 将用友切到动态网关，验证登录、跳转、上传、WebSocket 和原网站 Cookie；
5. 删除用友专属 Nginx/oauth2-proxy 服务模板，之后只允许控制台发布；
6. 增加发布闸门：发现应用依赖专属服务器文件时拒绝标记为标准产品。

## 验收标准

- 在一台新 Windows 电脑上，仅下载助手、输入安装码即可上线代理，过程中不执行 PowerShell；
- 管理员新建一个测试内网网站，从保存到公网 HTTPS 可访问，全程不登录 Cloudflare或服务器；
- 新应用创建前后，服务器 Git 工作树、Nginx主配置、systemd 单元数量和证书数量保持不变；
- 代理离线、内网端口拒绝、配置签名错误、隧道失败、网关未知 Host、授权被撤销均有独立自动测试；
- 修改配置失败时旧应用继续可用，页面显示期望/实际修订不一致；
- 停用应用后不能建立新会话，未知域名不能落入任意内网源站；
- 外部真实电脑完成微信扫码后直达原内网应用，页面资源、跳转、Cookie、上传与 WebSocket 工作正常；
- 新增第二、第三个应用重复上述流程，不能新增任何服务器专属代码或人工配置。

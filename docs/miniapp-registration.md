# 微信小程序注册信息（草案）

> 适用于：开发方代客户（物业公司）申请。两个小程序分别申请 AppID，主体可以是同一家物业公司，也可以是开发方主体（视代运营协议而定）。

## 通用前置准备

| 项 | 说明 |
|---|---|
| 主体类型 | 企业（物业公司营业执照），非个体户 |
| 法人 / 管理员手机号 | 用于扫脸验证、找回 |
| 对公账户 | 用于打款 1 分钱验证主体 |

| 业务域名 | 若使用 web-view，需备案并下载校验文件 |

### 为什么互换（2026-08-30）

员工端那个主体的认证卡住了，而 `wx.getPhoneNumber`（员工手机号一键登录的唯一入口，见本文末「员工端登录与微信绑定流程」）
要求小程序**企业主体已认证** —— 员工端在原 AppID 上根本发不出可用的版本。
业主端的 `wx002fde4bfaa4c7d9` 已经认证过，所以把它先让给员工端用，业主端暂挪到未认证的那个 AppID 上。

**代码目录、发版命令、品牌资源都没动**：员工端代码仍在 `apps/miniapp-staff/`，仍用 `pnpm mp:staff`，
`assets/brand-icon.png` 和「邻修工作台」这些还是员工端自己的 —— 换的只有它发到哪个 AppID。

互换要同时改三处，少一处就登录失败：

| 处 | 内容 |
|---|---|
| 仓库 | 两个 `project.config.json` 的 `appid`（已改） |
| 服务器 `.env` | `WX_OWNER_APPID/SECRET` 与 `WX_STAFF_APPID/SECRET` 整组对调，之后 `pm2 reload pms-api --update-env` |
| 公众平台（人工） | 两个小程序的**头像和名称**对调：`wx002fde4bfaa4c7d9` 换成 `tools/logos/logo-staff.png` +「邻修工作台」，`wx8ef4de0e498064c4` 换成 `logo-owner.png` +「邻修」 |

`appType`（`'owner'` / `'staff'`）是**代码侧的端标识**，不跟着 AppID 走：员工端小程序照旧调
`/auth/staff-login`，服务端照旧按 `appType='staff'` 去读 `WX_STAFF_*` —— 所以对调的是 `.env` 里那两组值，
不是代码里的 `appType`。

## 员工端登录与微信绑定流程

员工账号不自助注册，由管理员在后台「员工管理」预先建号（姓名 + 手机号 + 角色）。

1. 员工打开「邻修管理」→ 点「手机号快捷登录」
   → `wx.getPhoneNumber` 拿到 code → 后端 `POST /auth/staff-login` 用 `getuserphonenumber` 解出手机号
   → 匹配到该手机号的在职员工账号 → 绑定本微信 openid → 发双 token。
2. 非维修工角色（办公室/经理/采购/管理员）也可用「账号密码登录」兜底，登录成功同样完成绑定。
3. 已绑定过的员工再次进入小程序只用 `wx.login` 的 code 静默登录，无需再次授权手机号。
4. 换手机/换微信/人员变动：管理员在后台员工列表点「解绑微信」，员工再登录一次即可重新绑定。

风险控制：
- 一个微信只能绑一个员工账号；一个员工账号只能绑一个微信，冲突时提示联系管理员解绑。
- 手机号命中多个员工账号（跨物业公司重复）时拒绝手机号登录，提示改用账号密码。
- 账号停用（`status=disabled`）后立即无法登录，已发 token 由 `/auth/me` 与各接口的用户校验拦截。

前置条件（微信侧）：员工端小程序需**企业主体已认证**才能使用「获取手机号」接口，
并在「小程序后台 → 设置 → 用户隐私保护指引」中声明 `wx.getPhoneNumber` 用途。

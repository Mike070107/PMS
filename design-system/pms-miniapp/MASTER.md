# PMS 小程序设计规范

适用于“邻修”业主端与“邻修管理”员工端。员工端主要使用者包含年纪较大的维修人员，界面首先保证看得清、点得准、操作路径短，再考虑装饰效果。

## 一、按钮

### 1. 布局基线

- 所有微信原生 `button` 必须清除默认外边距和 `::after` 边框。
- 所有按钮默认使用 `display: flex`、`align-items: center`、`justify-content: center` 和 `box-sizing: border-box`。
- 必须重置微信原生约 2.55 倍的 `line-height`；单行按钮建议 `line-height: 1` 至 `1.2`，禁止依赖原生行高实现居中。
- 文字和图标必须同时水平、垂直居中。带图标时图标不参与压缩，图标与文字间距保持一致。
- 业务专用按钮即使没有使用公共 `.btn`，也必须继承上述布局基线；只有语音说明等明确的多行按钮可以覆盖为左对齐。

### 2. 尺寸与可点击性

- 主要操作按钮高度建议 `96rpx` 至 `112rpx`，最低不得小于 `88rpx`。
- 小型辅助按钮的可点击高度最低为 `72rpx`；确因预览缩放等紧凑场景需要更小时，整个操作组仍应提供足够的点击间距。
- 并排按钮应等高，文字较长时优先扩大宽度或换行，不得通过压缩字号解决。
- 同一层级且经常连续比较的两个辅助操作，手机端优先左右并排；只有一个操作时自动占满整行，说明文字另占一整行。
- 按钮左右内边距不得小于 `20rpx`，相邻按钮间距不得小于 `16rpx`。

### 3. 状态与层级

- 一个操作区只保留一个视觉最强的主按钮；返回、取消、撤回等使用描边或浅色次按钮。
- 危险操作使用红色系，但不得仅靠颜色表达风险，按钮文字必须明确写出“删除”“作废”“撤回”等动作。
- 加载时保留按钮原有高度和宽度，显示加载态并禁止重复点击。
- 禁用态应降低透明度，同时保留可辨识文字；不得用几乎看不见的浅灰色。
- 点击态只能改变透明度、背景或阴影，不得缩放导致页面跳动。

## 二、文字与信息层级

- 员工端正文建议不小于 `32rpx`，按钮正文建议不小于 `34rpx`，辅助说明建议不小于 `26rpx`。
- 地址、当前状态、下一步操作属于工单最高优先级信息，应在卡片首屏清晰展示。
- 一段说明超过两行时应分段或使用项目符号，避免把操作提示挤进按钮。
- 关键字段不得仅用颜色区分，还需配合标签、标题或状态文字。

## 三、表单与操作流程

- 一个页面或弹层只解决一个主要任务，主操作固定在用户自然阅读顺序的末尾。
- 需要输入较多文字的字段优先提供语音输入，并允许识别后手工修改。
- AI 从语音中识别出的材料只能作为核对提醒；必须由维修工手动选择真实仓库和 SKU 后，才能进入用料清单或参与扣库。
- 必填项在输入前说明，错误提示紧邻对应字段，不能只用顶部提示后让用户自行寻找。
- 撤回、转单、作废等影响流程的操作必须先说明结果，再要求填写原因，确认后写入工单进度。

## 四、移动端验收清单

每次新增或修改页面，至少检查以下项目：

- [ ] 所有按钮文字在不同机型上上下居中，没有贴顶或贴底。
- [ ] 主按钮、次按钮和加载状态切换时尺寸不跳动。
- [ ] 最小点击区域符合规范，单手操作不易误触。
- [ ] 长姓名、长地址、长按钮文案不会相互挤压或超出屏幕。
- [ ] 页面在系统字体放大后仍能完成主要操作。
- [ ] 固定底栏不会遮挡最后一项内容，并已计入安全区。
- [ ] 空数据、加载、错误、禁用四种状态均有明确反馈。
- [ ] 语音按钮的按住、松开、取消状态清楚且不会误提交。

## 五、实现约定

- 全局按钮归一化放在各小程序的 `miniprogram/app.wxss`。
- 通用尺寸、字号和颜色优先使用 `packages/miniapp-ui` 中的设计令牌。
- 页面样式只定义该页面独有的布局和视觉差异，不重复实现公共按钮基础规则。
- 若业务按钮需要偏离本规范，必须在对应 WXSS 旁写明场景和原因，并在真机上单独验收。

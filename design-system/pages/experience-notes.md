# 维修经验总结页面规范

本页在 Web 与员工小程序中共用同一种内容模型。目标是让维修工像使用飞书文档一样整理图文经验，同时不要求年纪较大的用户学习 Markdown 语法。

## 编辑模式

- 默认进入“可视化”模式；Markdown 是高级入口，不得作为首次打开时的默认模式。
- 可视化与 Markdown 切换必须无损，切回可视化后立即看到真实阅读排版。
- 标题始终使用独立、可见的标题输入框，不藏进 Markdown 正文。
- Web 支持导入、导出 `.md`；小程序提供可粘贴的 Markdown 编辑区和“复制 Markdown”。

## 内容块

- 支持正文、小标题、项目符号、编号步骤、待办项、引用、注意事项、图片、分隔线。
- 一段内容一个块，移动和删除作用于整个块；不得用难点中的拖拽作为唯一排序方式，始终保留“上移/下移”。
- 图片用于辨认维修现场，使用 `contain/aspectFit`，不得裁切关键信息。
- 注意事项使用琥珀色左边框，引用使用灰蓝色左边框；一屏不再增加其他高饱和语义色。
- 语音识别只写入当前文字块，识别后仍可编辑，不自动保存。

## Markdown 子集

- 块级：`## 标题`、`- 项目`、`1. 步骤`、`- [ ] 待办`、`> 引用`、`> [!WARNING]`、图片和分隔线。
- 行内：`**加粗**`、`*斜体*`、反引号代码和 `https` 链接。
- 未识别语法按普通正文保留，不能因为转换而静默丢字。
- 渲染前必须转义 HTML；链接只允许 `http`、`https`。

## 移动端

- 正文、按钮和输入区遵守员工端大字号、最小 `88rpx` 触控目标规范。
- 内容类型工具栏横向滚动，不挤压按钮文字，不让整页横向溢出。
- 阅读页只有“复制 Markdown”和“编辑这篇经验”两个末尾操作；无编辑权时复制按钮独占整行。

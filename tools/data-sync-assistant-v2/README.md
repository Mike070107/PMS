# PMS 数据同步助手

本版本把旧版每台电脑一个代理程序，合并为一个可管理多种连接的 Windows 应用和后台服务。

## 已接入能力

- 2.6.0（固定安装入口）：安装程序不再要求用户自行挑 D 盘目录。程序放到 Program Files 的 PMS 固定目录，桌面/开始菜单/登录托盘共用不可变启动器；前台、后台自动更新和旧版更新命令共用安装事务。新版服务提交本机路径/PID/新鲜健康证据后才切换入口；失败恢复原服务路径和运行状态，恢复失败明确报警并保留恢复记录。只清理可验证的托管旧程序，配置、DPAPI 密钥和业务快照不删除。此处“本机就绪”不代表联网、数据库、控制器或现场刷卡验收。

- 2.5.54（换牌原值保护，现场安装以实际版本为准）：换牌逐库保留原车型、授权及完整业务原值；独立修改车辆类型仅改所选库的身份字段。写前保存本机 DPAPI typed 原值快照，完整读回校验后才成功；丢回执只能由原助手使用原快照恢复。新增 `parkingVehiclePreservationV1` 能力，须配套本批 API/Web。更新包发布不等于现场已安装，真实 SQL 事务、现场跨进程恢复与设备仍须单独验收。

- 2.5.53（停车心跳修复，现场安装以实际版本为准）：停车只读心跳独立于慢权限探测和最长 60 秒的业务任务；写权限缓存保守过期，窗口与托盘按 15 秒真实心跳新鲜度显示。不会放宽 API 在线阈值，也不把旧库写队列当设备完成。Release/x86 与离线自检通过；本机构建缺 .NET 4 targeting pack，使用 GAC 引用，不代替真正 .NET 4 现场兼容性、停车 SQL 或设备验收。发布证据见既有停车实施文档；现有每 6 小时客户端自动检查行为不变。

## 从旧版升级

1. 从正式更新清单的 `installerUrl` 下载 `Pms.DataSyncAssistant.Setup.exe`，双击并确认安装，允许管理员授权。兼容旧更新器的 `Pms.DataSyncAssistant.V2.exe` 与安装程序为同一份单文件程序，均可双击安装。
2. 程序会扫描已知旧版目录并保留已有代理 ID、密钥、数据库路径和密码。V2 原服务切换到固定安装目录；更早的分类型服务仍走既有“验证连接 → 停旧 → 验证新 → 删除旧服务”流程，不跳过旧服务迁移验证；若外部健康延迟但新版服务仍运行，保留旧服务注册供后续确认。
3. 成功后用桌面或开始菜单的“PMS 数据同步助手”打开，不再从下载文件夹或旧 D 盘副本启动。已打开的旧窗口/托盘可以继续显示旧版本，退出后从固定入口重开即可；不要自行删除正在使用的旧目录。
4. 在连接卡片逐项确认数据库、PMS 和设备状态。成功安装只证明服务本机初始化并持续发布健康证据，不代表外部业务在线。
5. 安装期间不要关机；若中断，下次重新运行安装包会先按持久事务记录恢复原服务与入口，再重试。回退失败会明确显示错误，保留 `installation-pending.json`，请保留目录联系维护人员，不要手动删除恢复记录。

程序目录：32 位进程的 `%ProgramFiles%\PMS\DataSyncAssistant`（64 位 Windows 通常为 `C:\Program Files (x86)\PMS\DataSyncAssistant`）。固定入口为根目录 `Pms.DataSyncAssistant.exe`，服务载荷位于 `releases\<版本>\Pms.DataSyncAssistant.V2.exe`。不要把原版同名 0.x 单机程序误当此固定入口。

配置仍保存在 `%ProgramData%\PMS\DataSyncAssistant`，不搬迁、不重新加密。卸载后台服务不会删除连接配置或密码。

清理边界：保留当前和上一托管版本；占用中、无法确认进程路径、带未知文件/子目录、没有校验标记或重解析链接的目录均不清理。原非托管目录不删除。仅清理 ProgramData 下 `updates` / `releases` 内超过 7 天、未占用的已知安装包文件，保留前一服务可执行文件、离线清单和所有配置/密钥/业务快照。旧程序被占用时延后到下次安装/更新清理，异常写入系统诊断 Trace；清理保留原因写入程序目录 `cleanup-warnings.txt`；清理失败不撤销已提交的安装。快捷方式设置失败会明确提示固定入口路径，不会冒充已生成入口。

## 发布更新清单

更新清单默认地址为 `https://prsznh.cn/downloads/pms-data-sync-assistant/latest.json`，格式见 `update-manifest.example.json`。清单和 EXE 必须通过 HTTPS 发布，且 `sha256` 必须填写发布 EXE 的完整 SHA-256。测试环境可设置 `PMS_ASSISTANT_UPDATE_MANIFEST_URL`，或把 `latest.json` 放到 `%ProgramData%\PMS\DataSyncAssistant\updates\` 做离线验收。

## 命令行诊断

```powershell
.\Pms.DataSyncAssistant.V2.exe --self-test
```

退出代码 `0` 表示配置、DPAPI、运行参数映射、旧版 `.88` 迁移、停车住户栏位映射及更新器自检通过，包括安装事务的故障注入、持久记录恢复、配置/密钥哈希保留、清理边界回归。该自检的服务接口为隔离替身，不冒充真实 SCM。

管理员另运行 `./verify-installation.ps1 -EvidenceDirectory <证据目录>`：使用随机 `PmsAssistantInstallTest_*` 真实 Windows 服务验证创建/启动、路径/PID 就绪、注入就绪失败、真实旧服务路径回退、原停止状态恢复及重试；最终删除测试服务。只在项目 obj 目录写测试文件，不触碰正式服务/ProgramData/业务连接。需先构建；正式发布时自动运行该冒烟。

## 发布新版

`publish-update.ps1` 会从 Release x86 重新构建，运行自检，然后生成带 SHA-256 的 `release/latest.json` 和版本目录。默认只在本地生成；只有明确要求发布生产时才使用：

```powershell
# 在仓库根目录执行，先合入并推送 main；不要从未提交源码直接上传。
.\deploy\publish-production.ps1 -Target assistant
```

客户端只接受 `https://prsznh.cn/downloads/pms-data-sync-assistant/` 下的文件，且必须同时通过 SHA-256 和 Windows 文件版本校验。版本目录同时发布 Setup 与 V2 两个同哈希入口，保留旧客户端兼容字段。发布前运行真实 SCM 冒烟；服务端校验上传 SHA 后先放版本文件，再原子替换清单并留 `latest.previous.json`。发布后回读清单版本/提交及两个公网 EXE 的版本与 SHA，成功才标记 deployed/assistant。

兼容与边界：目标仍为 x86 / .NET Framework 4 / C# 5；本机构建缺 .NET 4 targeting pack，会使用 GAC 引用，因此真实 Win7/.NET4-only 现场兼容性未获验证。安装包未加 Authenticode 签名，不应宣称已消除 Windows SmartScreen 提示。本次为自安装 EXE，不是 MSI；现有“卸载后台服务”不是完整产品卸载器，不删除程序/快捷方式/HKLM 登录入口/配置。安装/升级不等于现场已升级或硬件已确认。
